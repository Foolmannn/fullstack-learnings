# Parallel Routes in Next.js — In Detail

**Parallel Routes** are an advanced routing feature of the **Next.js App Router** that allows you to render **multiple pages or UI sections simultaneously within the same layout**.

They are especially useful for:

* Dashboards
* Admin panels
* Modal routes
* Split-screen interfaces
* Independent sections of a page
* Tabs that have their own routes
* Complex applications where different sections need independent navigation/loading states

The key idea is:

> **Parallel Routes allow a layout to render multiple route segments at the same time using named slots.**

---

# 1. The Problem Parallel Routes Solve

Suppose you have a dashboard:

```text
+------------------------------------------------+
|                  Dashboard                      |
+----------------+-------------------------------+
|                |                               |
|   Sidebar      |       Main Content            |
|                |                               |
|                |                               |
+----------------+-------------------------------+
```

Normally, your route structure might look like:

```text
/dashboard
/dashboard/profile
/dashboard/settings
/dashboard/analytics
```

When navigating between these routes, the main page changes.

But imagine you want something more complex:

```text
+------------------+-----------------------------+
|                  |                             |
|   Notifications  |       Main Dashboard        |
|                  |                             |
+------------------+-----------------------------+
|                  |                             |
|   Messages       |       Analytics             |
|                  |                             |
+------------------+-----------------------------+
```

You might want the **notifications section**, **messages section**, and **main dashboard section** to have independent routing.

That's where **Parallel Routes** are useful.

---

# 2. Basic Concept

Parallel Routes use folders beginning with:

```text
@
```

For example:

```text
app/
└── dashboard/
    ├── layout.tsx
    ├── page.tsx
    ├── @analytics/
    │   └── page.tsx
    └── @team/
        └── page.tsx
```

Here:

```text
@analytics
@team
```

are **named slots**.

The `@` is special syntax recognized by Next.js.

---

# 3. Understanding Slots

Consider:

```text
app/dashboard/
```

with:

```text
@analytics/
@team/
```

These are not normal URL segments.

For example:

```text
/dashboard/@analytics
```

is **not** the URL.

Instead, `@analytics` creates a slot that is passed to the layout.

Your URL can still simply be:

```text
/dashboard
```

The layout receives:

```tsx
analytics
team
```

as props.

---

# 4. Basic Example

Directory structure:

```text
app/
└── dashboard/
    ├── layout.tsx
    ├── page.tsx
    ├── @analytics/
    │   └── page.tsx
    └── @team/
        └── page.tsx
```

### `@analytics/page.tsx`

```tsx
export default function Analytics() {
  return (
    <div>
      <h2>Analytics</h2>
      <p>Analytics information</p>
    </div>
  );
}
```

### `@team/page.tsx`

```tsx
export default function Team() {
  return (
    <div>
      <h2>Team</h2>
      <p>Team information</p>
    </div>
  );
}
```

Now the important part is the layout.

### `layout.tsx`

```tsx
export default function DashboardLayout({
  children,
  analytics,
  team,
}: {
  children: React.ReactNode;
  analytics: React.ReactNode;
  team: React.ReactNode;
}) {
  return (
    <div>
      <h1>Dashboard</h1>

      {children}

      <div>
        {analytics}
      </div>

      <div>
        {team}
      </div>
    </div>
  );
}
```

Now Next.js renders:

```text
Dashboard

Main Dashboard

Analytics

Team
```

all through the same layout.

# 5. What Is `children`?

This is extremely important.

Suppose you have:

```text
app/dashboard/
├── page.tsx
├── @analytics/
│   └── page.tsx
└── @team/
    └── page.tsx
```

There are effectively three pieces:

```text
children
analytics
team
```

The default `page.tsx` becomes:

```tsx
children
```

The:

```text
@analytics
```

folder becomes:

```tsx
analytics
```

And:

```text
@team
```

becomes:

```tsx
team
```

So:

```tsx
export default function Layout({
  children,
  analytics,
  team,
}) {
```

means:

```text
children  → dashboard/page.tsx

analytics → dashboard/@analytics/page.tsx

team      → dashboard/@team/page.tsx
```

# 6. Visualizing It

Think of the layout like a function:

```text
                    Dashboard Layout
                          |
          +---------------+---------------+
          |               |               |
       children        analytics         team
          |               |               |
     dashboard/       @analytics/       @team/
       page.tsx          page.tsx        page.tsx
```

The layout decides **where each slot appears**.

For example:

```tsx
return (
  <div className="grid grid-cols-3">
    
    <main>
      {children}
    </main>

    <aside>
      {analytics}
    </aside>

    <aside>
      {team}
    </aside>

  </div>
);
```

# 7. Parallel Routes Are Not URL Routes

This is one of the most common points of confusion.

Suppose:

```text
app/dashboard/
├── page.tsx
├── @analytics/
│   └── page.tsx
└── @team/
    └── page.tsx
```

You might think the URLs are:

```text
/dashboard
/dashboard/@analytics
/dashboard/@team
```

❌ Wrong.

The `@` folders are **slots**, not URL segments.

The route is still:

```text
/dashboard
```

The slots are rendered inside that route.

---

# 8. Why Are They Called Parallel Routes?

Because multiple route branches can be rendered **in parallel**.

For example:

```text
                  /dashboard
                       |
          +------------+------------+
          |            |            |
          ↓            ↓            ↓
       children     analytics      team
          |            |            |
          ↓            ↓            ↓
       Dashboard    Analytics      Team
```

Instead of having:

```text
/dashboard
      ↓
/dashboard/analytics
      ↓
/dashboard/team
```

you can have:

```text
/dashboard

   ├── Dashboard
   ├── Analytics
   └── Team
```

at the same time.

---

# 9. Parallel Routes with Loading States

One major advantage is that different slots can have their own loading UI.

Example:

```text
app/
└── dashboard/
    ├── layout.tsx
    ├── page.tsx
    │
    ├── @analytics/
    │   ├── page.tsx
    │   └── loading.tsx
    │
    └── @team/
        ├── page.tsx
        └── loading.tsx
```

Analytics can have:

```tsx
export default function Loading() {
  return <p>Loading analytics...</p>;
}
```

Team can have:

```tsx
export default function Loading() {
  return <p>Loading team...</p>;
}
```

This allows different sections to handle loading independently.

---

# 10. `default.tsx`

Another important concept with Parallel Routes is:

```text
default.tsx
```

Suppose:

```text
app/dashboard/
├── layout.tsx
├── page.tsx
├── @analytics/
│   ├── page.tsx
│   └── default.tsx
└── @team/
    ├── page.tsx
    └── default.tsx
```

`default.tsx` provides a fallback UI when Next.js cannot determine an active page for a slot during navigation or initial rendering.

For example:

```tsx
export default function DefaultAnalytics() {
  return (
    <div>
      No analytics page selected.
    </div>
  );
}
```

# 11. Parallel Routes and Conditional Rendering

Parallel Routes become particularly powerful when combined with route state.

Imagine an application with:

```text
Dashboard
├── Main Content
├── Notifications
└── Login
```

You could create:

```text
app/
└── dashboard/
    ├── layout.tsx
    ├── page.tsx
    │
    ├── @main/
    │   └── page.tsx
    │
    ├── @notifications/
    │   └── page.tsx
    │
    └── @auth/
        └── page.tsx
```

The layout can control where they appear:

```tsx
export default function Layout({
  main,
  notifications,
  auth,
}) {
  return (
    <>
      {main}

      <aside>
        {notifications}
      </aside>

      {auth}
    </>
  );
}
```

# 12. Parallel Routes vs Normal Nested Routes

This distinction is important.

### Normal nested routes

```text
app/
└── dashboard/
    ├── page.tsx
    ├── analytics/
    │   └── page.tsx
    └── settings/
        └── page.tsx
```

URLs:

```text
/dashboard
/dashboard/analytics
/dashboard/settings
```

Generally, one route's page occupies the main route area.

---

### Parallel Routes

```text
app/
└── dashboard/
    ├── layout.tsx
    ├── page.tsx
    ├── @analytics/
    │   └── page.tsx
    └── @settings/
        └── page.tsx
```

The layout receives:

```tsx
children
analytics
settings
```

and can display them simultaneously.

---

# 13. Parallel Routes vs Route Groups

Don't confuse:

```text
@analytics
```

with:

```text
(analytics)
```

They have completely different purposes.

### Route Group

```text
(analytics)
```

is used to organize routes without affecting the URL.

Example:

```text
app/
└── (dashboard)/
    ├── dashboard/
    └── settings/
```

The parentheses don't appear in the URL.

---

### Parallel Route

```text
@analytics
```

creates a **named slot**.

The slot becomes a prop in the parent layout.

```tsx
function Layout({ analytics }) {
```

So:

```text
(...) → organization

@... → parallel UI slot
```

# 14. Parallel Routes + Dynamic Routes

You can also combine them with dynamic segments.

For example:

```text
app/
└── dashboard/
    ├── layout.tsx
    │
    ├── @users/
    │   └── [id]/
    │       └── page.tsx
    │
    └── @analytics/
        └── page.tsx
```

Now one slot can represent a specific user:

```text
/dashboard/users/123
```

while another slot can display analytics.

This becomes useful in complex dashboards.

# 15. Tabs with Parallel Routes

Parallel Routes can also be used to build tab-like interfaces.

Example:

```text
app/
└── dashboard/
    ├── layout.tsx
    ├── page.tsx
    ├── @overview/
    │   └── page.tsx
    └── @activity/
        └── page.tsx
```

The layout could render:

```tsx
<div>
  <nav>
    <Link href="/dashboard">Overview</Link>
    <Link href="/dashboard/activity">Activity</Link>
  </nav>

  {overview}
  {activity}
</div>
```

However, for simple tabs, **normal nested routes are often easier**. Parallel Routes are more appropriate when multiple independently routed UI regions need to coexist.

# 16. A Very Important Use Case: Modals

One of the most interesting uses of Parallel Routes is **modal routing**.

Imagine you're on:

```text
/products
```

You click:

```text
Product 123
```

Instead of replacing the whole page, you want:

```text
+--------------------------------+
|          Products              |
|                                |
|     +----------------------+   |
|     | Product 123          |   |
|     |                      |   |
|     | Details              |   |
|     |                      |   |
|     +----------------------+   |
|                                |
+--------------------------------+
```

The background page remains visible while the product details appear as a modal.

Parallel Routes can help implement this pattern.

A typical structure might involve:

```text
app/
├── layout.tsx
├── products/
│   ├── page.tsx
│   └── [id]/
│       └── page.tsx
│
└── @modal/
    ├── default.tsx
    └── (.)products/
        └── [id]/
            └── page.tsx
```

Notice this:

```text
(.)
```

That's a **route interception** convention.

So modal implementations often combine:

```text
Parallel Routes
        +
Intercepting Routes
```

This is a more advanced Next.js routing pattern.

---

# 17. Parallel Routes + Intercepting Routes

This combination is worth understanding.

Suppose you have:

```text
/products
```

and:

```text
/products/123
```

Normally:

```text
/products/123
```

replaces the products page.

But with interception, you can make:

```text
/products/123
```

appear as a modal when navigating from `/products`.

The structure might look conceptually like:

```text
app/
├── products/
│   ├── page.tsx
│   └── [id]/
│       └── page.tsx
│
└── @modal/
    └── (.)products/
        └── [id]/
            └── page.tsx
```

Then:

```text
/products
     |
     | click Product 123
     ↓
/products/123
```

can result in:

```text
Background:
Products page

Foreground:
Product 123 modal
```

This is one of the most powerful routing patterns in the App Router.

# 18. Independent Navigation

Another advantage is that each slot can have its own navigation state.

Imagine:

```text
Dashboard
│
├── Main
│
├── Team
│
└── Notifications
```

You might navigate the Team section without replacing the entire dashboard layout.

Conceptually:

```text
Dashboard Layout
│
├── Main Slot
│     └── /dashboard
│
├── Team Slot
│     └── Team-related route
│
└── Notifications Slot
      └── Notification-related route
```

This allows sophisticated applications to maintain different UI areas simultaneously.

# 19. Error Handling with Parallel Routes

You can also have an error boundary for a particular slot.

For example:

```text
app/dashboard/
├── layout.tsx
│
├── @analytics/
│   ├── page.tsx
│   └── error.tsx
│
└── @team/
    ├── page.tsx
    └── error.tsx
```

If Analytics encounters an error:

```text
+------------------------------+
| Dashboard                    |
+------------------------------+
|                              |
| Analytics                    |
|                              |
| Something went wrong         |
|                              |
+------------------------------+
| Team                         |
|                              |
| Team data is working         |
+------------------------------+
```

The Team section doesn't necessarily need to fail just because Analytics failed.

That's an important advantage of independently routed UI.

# 20. `loading.tsx`, `error.tsx`, and `default.tsx`

Parallel Routes work especially well with the App Router's special files.

For example:

```text
app/dashboard/
│

├── page.tsx
│
├── @analytics/
│   ├── page.tsx
```

```text

```

This gives you fine-grained control over UI states.

# 23. Parallel Routes Mental Model

A good way to understand it is:

### Normal routing

```text
URL
 ↓
Route
 ↓
Page
```

### Parallel routing

```text
                 Layout
                    |
       +------------+------------+
       |            |            |
       ↓            ↓            ↓
    children     analytics      team
       |            |            |
       ↓            ↓            ↓
     Page         Page          Page
```

The **layout is the orchestrator**.

It decides:

```tsx
{children}
{analytics}
{team}
```

where each piece appears.

# 24. Important Naming Rule

Suppose you create:

```text
@users
```

Then your layout receives:

```tsx
users
```

If you create:

```text
@notifications
```

you get:

```tsx
notifications
```

If you create:

```text
@analytics
```

you get:

```tsx
analytics
```

So:

```text
@something
```

becomes:

```tsx
something
```

inside the parent layout.

---

# 25. Parallel Routes Do Not Mean Parallel API Calls

This is another common misunderstanding.

"Parallel" doesn't primarily mean:

> "Next.js makes all my API requests simultaneously."

It means:

> **Multiple route segments/slots can be rendered within the same layout at the same time.**

Whether the underlying data requests execute concurrently depends on how your Server Components and data fetching are structured.

# 26. When Should You Use Parallel Routes?

Use Parallel Routes when you need:

### ✅ Multiple independent UI regions

```text
Dashboard
├── Main
├── Analytics
└── Notifications
```

### ✅ Independent loading states

```text
Analytics → Loading...

Team → Loaded
```

### ✅ Independent error boundaries

```text
Analytics → Error

Team → Working
```

### ✅ Modal routing

```text
Products
   +
Product Details Modal
```

### ✅ Complex dashboards

For example:

```text
+-------------------------------+
| Navbar                        |
+----------+--------------------+
| Sidebar  | Main               |
|          |                    |
|          +--------------------+
|          | Analytics          |
|          |                    |
+----------+--------------------+
```

# 27. When NOT to Use Parallel Routes

Don't use them simply because they're available.

For a simple application:

```text
/dashboard
/dashboard/profile
/dashboard/settings
```

normal nested routes are usually easier:

```text
dashboard/
├── page.tsx
├── profile/
│   └── page.tsx
└── settings/
    └── page.tsx
```

Parallel Routes add complexity.

Use them when you actually need **multiple independently routed UI regions**.

# 28. Parallel Routes vs Intercepting Routes

These two are often learned together.

| Feature             | Purpose                                    |
| ------------------- | ------------------------------------------ |
| Parallel Routes     | Render multiple route slots simultaneously |
| Intercepting Routes | Display a route in a different UI context  |
| Route Groups        | Organize routes without changing URL       |
| Dynamic Routes      | Create dynamic URL segments                |

For example, a modal system can use:

```text
Parallel Route
      +
Intercepting Route
      ↓
   Modal UI
```

---

# 29. Parallel Routes vs Layouts

They are closely related but different.

### Layout

A layout provides a shared UI:

```text
Navbar
Sidebar
Footer
```

Example:

```tsx
export default function Layout({ children }) {
  return (
    <>
      <Navbar />

      {children}

      <Footer />
    </>
  );
}
```

### Parallel Route

A Parallel Route provides another **named route slot**:

```tsx
export default function Layout({
  children,
  analytics,
}) {
  return (
    <>
      {children}

      {analytics}
    </>
  );
}
```

So:

```text
Layout → shared UI structure

Parallel Route → multiple named UI slots
```

## Final Mental Model

Think of a Parallel Route like a **named hole in a layout**.

```text
                 Dashboard Layout
                       │
        ┌──────────────┼──────────────┐
        │              │              │
        ▼              ▼              ▼
     children       analytics       team
        │              │              │
        ▼              ▼              ▼
    dashboard       charts         members
```

The folder:

```text
@analytics
```

doesn't primarily represent a URL.

It represents a **slot** that the parent layout can receive and render:

```tsx
{analytics}
```

That's the core concept behind **Parallel Routes in Next.js**.
