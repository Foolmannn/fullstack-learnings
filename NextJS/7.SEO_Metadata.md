# SEO in Next.js and Metadata

SEO (**Search Engine Optimization**) is the process of making your website easier for search engines like Google to **crawl, understand, index, and rank**.

Next.js is particularly good for SEO because it supports **server-side rendering, static generation, dynamic metadata, semantic HTML, image optimization, sitemaps, robots.txt, and structured data**.

---

## 1. Why SEO matters in Next.js

Suppose you have a blog page:

```text
https://example.com/blog/nextjs-seo
```

You want Google to understand:

* What is this page about?
* What should its title be?
* What description should appear in search results?
* What image should appear when the page is shared?
* Which URL is the canonical URL?
* Should search engines index this page?
* What keywords/topics are relevant?

Next.js provides a built-in **Metadata API** for many of these tasks.

---

# 2. Metadata in Next.js

Metadata is information about a web page that isn't normally displayed as the main page content.

For example:

```html
<title>Next.js SEO Guide</title>

<meta
  name="description"
  content="Learn how to implement SEO in Next.js."
/>
```

This metadata can help search engines and social-media platforms understand your page.

In modern Next.js App Router applications, metadata is generally defined using:

* `metadata` object
* `generateMetadata()` function

---

# 3. Static Metadata

The simplest approach is to export a `metadata` object from `layout.tsx` or `page.tsx`.

For example:

```tsx
import type { Metadata } from "next";

export const metadata: Metadata = {
  title: "Next.js SEO Guide",
  description: "Learn SEO and metadata in Next.js",
};

export default function Page() {
  return (
    <main>
      <h1>Next.js SEO Guide</h1>
      <p>Learn how SEO works in Next.js.</p>
    </main>
  );
}
```

Next.js will generate appropriate HTML metadata.

Conceptually:

```html
<head>
  <title>Next.js SEO Guide</title>
  <meta
    name="description"
    content="Learn SEO and metadata in Next.js"
  />
</head>
```

---

# 4. Metadata in `layout.tsx`

A very common pattern is to put **global metadata** in the root layout.

Structure:

```text
app/
├── layout.tsx
├── page.tsx
├── about/
│   └── page.tsx
└── blog/
    └── page.tsx
```

`app/layout.tsx`:

```tsx
import type { Metadata } from "next";

export const metadata: Metadata = {
  title: "My Website",
  description: "My awesome website",
};

export default function RootLayout({
  children,
}: {
  children: React.ReactNode;
}) {
  return (
    <html lang="en">
      <body>{children}</body>
    </html>
  );
}
```

This becomes the default metadata for pages underneath that layout.

---

# 5. Page-specific Metadata

You can override the global metadata on individual pages.

For example:

```tsx
// app/about/page.tsx

import type { Metadata } from "next";

export const metadata: Metadata = {
  title: "About Us",
  description: "Learn more about our company.",
};

export default function AboutPage() {
  return (
    <main>
      <h1>About Us</h1>
    </main>
  );
}
```

Now:

```text
/
```

might have:

```text
My Website
```

while:

```text
/about
```

has:

```text
About Us
```

---

# 6. Title Templates

One particularly useful feature is the title template.

Instead of manually writing:

```text
Home | My Website
About | My Website
Products | My Website
Contact | My Website
```

you can configure:

```tsx
export const metadata: Metadata = {
  title: {
    default: "My Website",
    template: "%s | My Website",
  },
  description: "My awesome website",
};
```

Then:

```tsx
export const metadata: Metadata = {
  title: "About",
};
```

produces:

```text
About | My Website
```

Another page:

```tsx
export const metadata: Metadata = {
  title: "Products",
};
```

produces:

```text
Products | My Website
```

This is extremely useful for larger applications.

# 7. Important Metadata Properties

The `Metadata` object supports many SEO-related properties.

For example:

```tsx
export const metadata: Metadata = {
  title: "Next.js SEO Guide",

  description:
    "A complete guide to SEO and metadata in Next.js.",

  keywords: [
    "Next.js",
    "SEO",
    "Next.js SEO",
    "metadata",
  ],
};
```

However, don't think of `keywords` as a magic ranking mechanism. Modern search engines don't generally use the `meta keywords` tag as a significant ranking factor.

Focus more on:

* useful content
* search intent
* page title
* description
* headings
* internal links
* crawlability
* performance
* structured data
* canonical URLs

# 8. Open Graph Metadata

Open Graph metadata controls how your page appears when shared on platforms that support Open Graph previews.

For example:

```tsx
export const metadata: Metadata = {
  title: "Next.js SEO Guide",
  description: "Learn SEO in Next.js",

  openGraph: {
    title: "Next.js SEO Guide",
    description: "Learn SEO in Next.js",
    url: "https://example.com/nextjs-seo",
    siteName: "My Website",
    images: [
      {
        url: "https://example.com/images/seo.png",
        width: 1200,
        height: 630,
        alt: "Next.js SEO Guide",
      },
    ],
    locale: "en_US",
    type: "article",
  },
};
```

This can generate metadata such as:

```html
<meta property="og:title" ... />
<meta property="og:description" ... />
<meta property="og:image" ... />
<meta property="og:url" ... />
```

---

# 9. Why Open Graph is important

Suppose someone shares:

```text
https://example.com/blog/nextjs-seo
```

Without proper metadata, the preview might look poor.

With Open Graph metadata, you can provide:

```text
┌───────────────────────────────────┐
│                                   │
│          [SEO IMAGE]              │
│                                   │
├───────────────────────────────────┤
│ Next.js SEO Guide                 │
│ Learn SEO in Next.js              │
│ example.com                       │
└───────────────────────────────────┘
```

This improves the appearance of shared links.

# 10. Twitter/X Metadata

Next.js also supports Twitter/X metadata.

For example:

```tsx
export const metadata: Metadata = {
  title: "Next.js SEO Guide",

  twitter: {
    card: "summary_large_image",
    title: "Next.js SEO Guide",
    description: "Learn SEO in Next.js",
    images: ["https://example.com/seo.png"],
  },

```

The `card` determines how the link preview can be presented.

# 11. Canonical URL

A canonical URL tells search engines which URL should be considered the primary version of a page.

For example, these could potentially represent the same content:

```text
https://example.com/products
https://example.com/products?sort=popular
https://example.com/products?ref=facebook
```

You can specify:

```tsx
export const metadata: Metadata = {
  alternates: {
    canonical: "https://example.com/products",
  },
};
```

Conceptually this generates:

```html
<link
  rel="canonical"
  href="https://example.com/products"
/>
```

Canonical URLs are useful for controlling duplicate/near-duplicate URL issues.

---

# 12. Robots Metadata

You can control whether search engines should index a page.

For example:

```tsx
export const metadata: Metadata = {
  robots: {
    index: false,
    follow: false,
  },
};
```

Conceptually:

```html
<meta
  name="robots"
  content="noindex,nofollow"
/>
```

This can be useful for pages such as:

```text
/dashboard
/account
/settings
/admin
```

where search indexing usually isn't desirable.

For a public page:

```tsx
export const metadata: Metadata = {
  robots: {
    index: true,
    follow: true,
  },
};
```

---

# 13. `robots.txt`

`robots.txt` is different from the `robots` metadata.

It tells crawlers which parts of your site they should generally avoid crawling.

In Next.js App Router you can create:

```text
app/
└── robots.ts
```

Example:

```tsx
import type { MetadataRoute } from "next";

export default function robots(): MetadataRoute.Robots {
  return {
    rules: {
      userAgent: "*",
      allow: "/",
      disallow: "/admin/",
    },

    sitemap: "https://example.com/sitemap.xml",
  };
}
```

Next.js can then serve:

```text
/robots.txt
```

---

# 14. Sitemap

A sitemap helps search engines discover URLs on your website.

Create:

```text
app/
└── sitemap.ts
```

Example:

```tsx
import type { MetadataRoute } from "next";

export default function sitemap(): MetadataRoute.Sitemap {
  return [
    {
      url: "https://example.com",
      lastModified: new Date(),
    },
    {
      url: "https://example.com/about",
      lastModified: new Date(),
    },
    {
      url: "https://example.com/blog",
      lastModified: new Date(),
    },
  ];
}
```

Next.js can expose:

```text
https://example.com/sitemap.xml
```

This is particularly useful when your website contains many pages.

# 15. Dynamic Metadata

This is one of the most important concepts.

Suppose you have:

```text
/blog/[slug]
```

Your URLs might be:

```text
/blog/nextjs-seo
/blog/react-server-components
/blog/typescript-guide
```

Each page needs different metadata.

You shouldn't hard-code:

```tsx
export const metadata = {
  title: "Blog",
};
```

Instead, use `generateMetadata()`.

---

# 16. `generateMetadata()`

Example:

```tsx
import type { Metadata } from "next";

type Props = {
  params: Promise<{
    slug: string;
  }>;
};

export async function generateMetadata({
  params,
}: Props): Promise<Metadata> {
  const { slug } = await params;

  return {
    title: slug,
    description: `Read our article about ${slug}`,
  };
}

export default async function Page({ params }: Props) {
  const { slug } = await params;

  return (
    <main>
      <h1>{slug}</h1>
    </main>
  );
}
```

Now:

```text
/blog/nextjs-seo
```

could produce:

```text
Title:
nextjs-seo

Description:
Read our article about nextjs-seo
```

In a real application, you would retrieve the actual blog post data.

---

# 17. Dynamic Metadata from a Database/API

Suppose your database contains:

```js
{
  slug: "nextjs-seo",
  title: "Complete Next.js SEO Guide",
  description: "Learn SEO in Next.js",
  image: "/images/nextjs-seo.png"
}
```

You can do:

```tsx
export async function generateMetadata({
  params,
}: Props): Promise<Metadata> {
  const { slug } = await params;

  const post = await getPost(slug);

  return {
    title: post.title,
    description: post.description,

    openGraph: {
      title: post.title,
      description: post.description,
      images: [post.image],
    },
  };
}
```

This is extremely useful for:

* blogs
* ecommerce
* news websites
* product pages
* documentation
* portfolios

# 18. Metadata Inheritance

Next.js supports metadata inheritance through layouts.

Imagine:

```text
app/
│
├── layout.tsx
│
├── page.tsx
│
├── blog/
│   ├── layout.tsx
│   ├── page.tsx
│   │
│   └── [slug]/
│       └── page.tsx
│
└── products/
    └── page.tsx
```

The root layout can provide:

```tsx
export const metadata: Metadata = {
  title: {
    default: "My Website",
    template: "%s | My Website",
  },
  description: "My website description",
};
```

Then the blog section can provide its own metadata.

This creates a hierarchy:

```text
Root Layout
     ↓
Blog Layout
     ↓
Blog Page
     ↓
Dynamic Blog Page
```

More specific metadata can override or extend metadata from parent layouts.

# 19. `metadataBase`

When working with relative URLs, `metadataBase` can be very useful.

For example:

```tsx
export const metadata: Metadata = {
  metadataBase: new URL("https://example.com"),

  title: {
    default: "My Website",
    template: "%s | My Website",
  },

  openGraph: {
    images: ["/images/og-image.png"],
  },
};
```

Now:

```text
/images/og-image.png
```

can be resolved relative to:

```text
https://example.com
```

resulting in:

```text
https://example.com/images/og-image.png
```

This is especially useful for Open Graph images and other metadata URLs.

# 21. Semantic HTML and SEO

Metadata alone doesn't make a website SEO-friendly.

Your actual HTML structure matters.

Bad:

```html
<div class="title">
  Next.js SEO
</div>
```

Better:

```html
<h1>Next.js SEO</h1>
```

Use semantic elements:

```html
<header>
<nav>
<main>
<article>
<section>
<aside>
<footer>
```

For example:

```tsx
<main>
  <article>
    <h1>Next.js SEO Guide</h1>

    <section>
      <h2>What is SEO?</h2>
      <p>...</p>
    </section>

    <section>
      <h2>Metadata in Next.js</h2>
      <p>...</p>
    </section>
  </article>
</main>
```

This makes the structure easier for search engines and assistive technologies to understand.

# 22. Headings

A page should generally have a clear primary heading.

For example:

```tsx
<h1>Next.js SEO Guide</h1>

<h2>Metadata</h2>
<h2>Sitemap</h2>
<h2>Robots.txt</h2>

<h3>Static Metadata</h3>
<h3>Dynamic Metadata</h3>
```

Think of headings as a hierarchy:

```text
H1
│
├── H2
│   ├── H3
│   └── H3
│
├── H2
│
└── H2
```

Don't use headings merely to make text visually larger.

# 23. SEO-Friendly URLs

Prefer:

```text
/blog/nextjs-seo
```

over:

```text
/blog?id=92837
```

Good URLs are:

* short
* descriptive
* readable
* stable
* relevant to the content

For example:

```text
/products/iphone-17
```

is much more meaningful than:

```text
/products/product?id=823728
```

Bad:


Better:

```tsx
alt="Next.js SEO architecture"
```

# 25. Internal Linking

Internal links help search engines discover and understand relationships between your pages.

In Next.js:

```tsx
import Link from "next/link";

<Link href="/blog/nextjs-seo">
  Learn about Next.js SEO
</Link>
```

Instead of:

```tsx
<a href="/blog/nextjs-seo">
```

`Link` provides Next.js navigation optimizations.

A good website might have:

```text
Home
 │
 ├── Blog
 │    ├── Next.js SEO
 │    ├── React
 │    └── TypeScript
 │
 ├── Products
 │
 └── About
```

This creates a useful internal-link structure.

# 26. Structured Data / JSON-LD

Structured data helps search engines understand the meaning of content.

For example, a blog article can be represented using `Article` structured data.

Conceptually:

```json
{
  "@context": "https://schema.org",
  "@type": "Article",
  "headline": "Next.js SEO Guide",
  "author": {
    "@type": "Person",
    "name": "John Doe"
  },
  "datePublished": "2026-08-26"
}
```

In Next.js, you can render JSON-LD in your page.

Example:

```tsx
const jsonLd = {
  "@context": "https://schema.org",
  "@type": "Article",
  headline: "Next.js SEO Guide",
  description: "Learn SEO in Next.js",
};

export default function Page() {
  return (
    <>
      <script
        type="application/ld+json"
        dangerouslySetInnerHTML={{
          __html: JSON.stringify(jsonLd),
        }}
      />

      <main>
        <h1>Next.js SEO Guide</h1>
      </main>
    </>
  );
}
```

Structured data is particularly useful for:

* articles
* products
* organizations
* events
* recipes
* FAQs
* breadcrumbs

Be careful that structured data accurately represents the visible content.

# 27. SEO and Server Components

Next.js App Router uses Server Components by default.

This is helpful for SEO because the server can generate HTML containing the page content.

For example:

```tsx
export default async function Page() {
  const products = await getProducts();

  return (
    <main>
      <h1>Products</h1>

      {products.map((product) => (
        <article key={product.id}>
          <h2>{product.name}</h2>
          <p>{product.description}</p>
        </article>
      ))}
    </main>
  );
}
```

The server can render the content before the browser receives the page.

---

# 28. Client Components and SEO

You shouldn't assume:

> Client Component = bad SEO

That's too simplistic.

Client Components can still be used in SEO-friendly applications.

The important question is **how and when the content is rendered**.

For important public content, a server-rendered approach is often preferable.

For example:

```tsx
"use client";

export default function Counter() {
  // interactive UI
}
```

There's no reason a counter needs to determine the SEO content of the page.

A good pattern is:

```text
Server Component
│
├── SEO content
├── headings
├── product information
│
└── Client Component
     └── interactive UI
```

---

# 29. Loading and SEO

Don't create a page where search engines/users initially receive almost nothing meaningful and everything depends on client-side fetching.

For example, instead of relying entirely on:

```tsx
"use client";

useEffect(() => {
  fetch("/api/products");
}, []);
```

you can often fetch data in a Server Component:

```tsx
export default async function Products() {
  const products = await getProducts();

  return (
    <main>
      <h1>Products</h1>

      {/* render products */}
    </main>
  );
}
```

This is generally a better architecture for public content.

For each important public page, think about:

### Metadata

```text
✓ Unique title
✓ Useful description
✓ Canonical URL
✓ Open Graph metadata
✓ Social sharing image
✓ Appropriate robots settings
```

### Content

```text
✓ One clear H1
✓ Proper H2/H3 hierarchy

✓ Search intent addressed
✓ Descriptive URLs
✓ Internal links
```

```text
✓ sitemap.xml
✓ robots.txt

✓ Mobile-friendly UI
✓ Fast page loading
✓ HTTPS
```

```text
✓ next/image
✓ meaningful alt text
✓ appropriate dimensions
```

### Structured Data

```text
✓ JSON-LD where appropriate
✓ Correct Schema.org type
✓ Structured data matches visible content
```

# 32. The Big Picture

Think about Next.js SEO as several layers:

```text
                    SEO
                     │
       ┌─────────────┼─────────────┐
       │             │             │
   Metadata       Content      Technical SEO
       │             │             │
       │             │             ├── Sitemap
       │             │             ├── Robots
       │             │             ├── Canonical
       │             │             └── URLs
       │             │
       │             ├── H1/H2
       │             ├── Useful content
       │             ├── Internal links
       │             └── Images
       │
       ├── Title
       ├── Description
       ├── Open Graph
       ├── Twitter
       ├── Icons
       └── Robots
```

The most important distinction to remember is:

**Metadata ≠ SEO.**

Metadata is only one part of SEO.

A technically perfect metadata setup won't make poor content rank well. A good SEO strategy combines **quality content + crawlability + good HTML structure + performance + internal linking + appropriate metadata + structured data**.

For modern Next.js, the key APIs/files to learn first are:

```text
Metadata
    ↓
metadata object
    ↓
generateMetadata()
    ↓
metadataBase
    ↓
Open Graph
    ↓
robots.ts
    ↓
sitemap.ts
    ↓
JSON-LD / Structured Data
```

These are the core pieces you'll repeatedly use when building production Next.js applications.
