# SEO in Next.js and Metadata

SEO (**Search Engine Optimization**) is the process of making your website easier for search engines like Google to **crawl, understand, index, and rank**.

Next.js is particularly good for SEO because it supports **server-side rendering, static generation, dynamic metadata, semantic HTML, image optimization, sitemaps, robots.txt, and structured data**.

---

## 1. Why SEO matters in Next.js

Suppose you have a blog page:

```text
https://example.com/blog/nextjs-seo
```

You want Google to understand:

* What is this page about?
* What should its title be?
* What description should appear in search results?
* What image should appear when the page is shared?
* Which URL is the canonical URL?
* Should search engines index this page?
* What keywords/topics are relevant?

Next.js provides a built-in **Metadata API** for many of these tasks.

---

# 2. Metadata in Next.js

Metadata is information about a web page that isn't normally displayed as the main page content.

For example:

```html
<title>Next.js SEO Guide</title>

<meta
  name="description"
  content="Learn how to implement SEO in Next.js."
/>
```

This metadata can help search engines and social-media platforms understand your page.

In modern Next.js App Router applications, metadata is generally defined using:

* `metadata` object
* `generateMetadata()` function

---

# 3. Static Metadata

The simplest approach is to export a `metadata` object from `layout.tsx` or `page.tsx`.

For example:

```tsx
import type { Metadata } from "next";

export const metadata: Metadata = {
  title: "Next.js SEO Guide",
  description: "Learn SEO and metadata in Next.js",
};

export default function Page() {
  return (
    <main>
      <h1>Next.js SEO Guide</h1>
      <p>Learn how SEO works in Next.js.</p>
    </main>
  );
}
```

Next.js will generate appropriate HTML metadata.

Conceptually:

```html
<head>
  <title>Next.js SEO Guide</title>
  <meta
    name="description"
    content="Learn SEO and metadata in Next.js"
  />
</head>
```

---

# 4. Metadata in `layout.tsx`

A very common pattern is to put **global metadata** in the root layout.

Structure:

```text
app/
├── layout.tsx
├── page.tsx
├── about/
│   └── page.tsx
└── blog/
    └── page.tsx
```

`app/layout.tsx`:

```tsx
import type { Metadata } from "next";

export const metadata: Metadata = {
  title: "My Website",
  description: "My awesome website",
};

export default function RootLayout({
  children,
}: {
  children: React.ReactNode;
}) {
  return (
    <html lang="en">
      <body>{children}</body>
    </html>
  );
}
```

This becomes the default metadata for pages underneath that layout.

---

# 5. Page-specific Metadata

You can override the global metadata on individual pages.

For example:

```tsx
// app/about/page.tsx

import type { Metadata } from "next";

export const metadata: Metadata = {
  title: "About Us",
  description: "Learn more about our company.",
};

export default function AboutPage() {
  return (
    <main>
      <h1>About Us</h1>
    </main>
  );
}
```

Now:

```text
/
```

might have:

```text
My Website
```

while:

```text
/about
```

has:

```text
About Us
```

# 6. Title Templates

One particularly useful feature is the title template.

Instead of manually writing:

```text
Home | My Website
About | My Website
Products | My Website
Contact | My Website
```

you can configure:

```tsx
export const metadata: Metadata = {
  title: {
    default: "My Website",
    template: "%s | My Website",
  },
  description: "My awesome website",
};
```

Then:

```tsx
export const metadata: Metadata = {
  title: "About",
};
```

produces:

```text
About | My Website
```

Another page:

```tsx
export const metadata: Metadata = {
  title: "Products",
};
```

produces:

```text
Products | My Website
```

This is extremely useful for larger applications.

# 7. Important Metadata Properties

The `Metadata` object supports many SEO-related properties.

For example:

```tsx
export const metadata: Metadata = {
  title: "Next.js SEO Guide",

  description:
    "A complete guide to SEO and metadata in Next.js.",

  keywords: [
    "Next.js",
    "SEO",
    "Next.js SEO",
    "metadata",
  ],
};
```

However, don't think of `keywords` as a magic ranking mechanism. Modern search engines don't generally use the `meta keywords` tag as a significant ranking factor.

Focus more on:

* useful content
* search intent
* page title
* description
* headings
* internal links
* crawlability
* performance
* structured data
* canonical URLs

# 8. Open Graph Metadata

Open Graph metadata controls how your page appears when shared on platforms that support Open Graph previews.

For example:

```tsx
export const metadata: Metadata = {
  title: "Next.js SEO Guide",
  description: "Learn SEO in Next.js",

  openGraph: {
    title: "Next.js SEO Guide",
    description: "Learn SEO in Next.js",
    url: "https://example.com/nextjs-seo",
    siteName: "My Website",
    images: [
      {
        url: "https://example.com/images/seo.png",
        width: 1200,
        height: 630,
        alt: "Next.js SEO Guide",
      },
    ],
    locale: "en_US",
    type: "article",
  },
};
```

This can generate metadata such as:

```html
<meta property="og:title" ... />
<meta property="og:description" ... />
<meta property="og:image" ... />
<meta property="og:url" ... />
```

---

# 9. Why Open Graph is important

Suppose someone shares:

```text
https://example.com/blog/nextjs-seo
```

Without proper metadata, the preview might look poor.

With Open Graph metadata, you can provide:

```text
┌───────────────────────────────────┐
│                                   │
│          [SEO IMAGE]              │
│                                   │
├───────────────────────────────────┤
│ Next.js SEO Guide                 │
│ Learn SEO in Next.js              │
│ example.com                       │
└───────────────────────────────────┘
```

This improves the appearance of shared links.

# 10. Twitter/X Metadata

Next.js also supports Twitter/X metadata.

For example:

```tsx
export const metadata: Metadata = {
  title: "Next.js SEO Guide",

  twitter: {
    card: "summary_large_image",
    title: "Next.js SEO Guide",
    description: "Learn SEO in Next.js",
    images: ["https://example.com/seo.png"],
  },
};
```

The `card` determines how the link preview can be presented.

# 11. Canonical URL

A canonical URL tells search engines which URL should be considered the primary version of a page.

For example, these could potentially represent the same content:

```text
https://example.com/products
https://example.com/products?sort=popular
https://example.com/products?ref=facebook
```

You can specify:

```tsx
export const metadata: Metadata = {
  alternates: {
    canonical: "https://example.com/products",
  },
};
```

Conceptually this generates:

```html
<link
  rel="canonical"
  href="https://example.com/products"
/>
```

Canonical URLs are useful for controlling duplicate/near-duplicate URL issues.

---

# 12. Robots Metadata

You can control whether search engines should index a page.

For example:

```tsx
export const metadata: Metadata = {
  robots: {
    index: false,
    follow: false,
  },
};
```

Conceptually:

```html
<meta
  name="robots"
  content="noindex,nofollow"
/>
```

This can be useful for pages such as:

```text
/dashboard
/account
/settings
/admin
```

where search indexing usually isn't desirable.

For a public page:

```tsx
export const metadata: Metadata = {
  robots: {
    index: true,
    follow: true,
  },
};
```

# 13. `robots.txt`

`robots.txt` is different from the `robots` metadata.

It tells crawlers which parts of your site they should generally avoid crawling.

In Next.js App Router you can create:

```text
app/
└── robots.ts
```

Example:

```tsx
import type { MetadataRoute } from "next";

export default function robots(): MetadataRoute.Robots {
  return {
    rules: {
      userAgent: "*",
      allow: "/",
      disallow: "/admin/",
    },

    sitemap: "https://example.com/sitemap.xml",
  };
}
```

Next.js can then serve:

```text
/robots.txt
```

---

# 14. Sitemap

A sitemap helps search engines discover URLs on your website.

Create:

```text
app/
└── sitemap.ts
```

Example:

```tsx
import type { MetadataRoute } from "next";

export default function sitemap(): MetadataRoute.Sitemap {
  return [
    {
      url: "https://example.com",
      lastModified: new Date(),
    },
    {
      url: "https://example.com/about",
      lastModified: new Date(),
    },
    {
      url: "https://example.com/blog",
      lastModified: new Date(),
    },
  ];
}
```

Next.js can expose:

```text
https://example.com/sitemap.xml
```

This is particularly useful when your website contains many pages.
