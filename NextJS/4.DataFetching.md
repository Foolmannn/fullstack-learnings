# Data Fetching in Next.js — Detailed Guide

Data fetching is one of the most important parts of Next.js because Next.js supports **Server Components, Client Components, Server Actions, Route Handlers, caching, revalidation, and streaming**.

If you already know React, the biggest conceptual shift is:

> **In traditional React, you often fetch data in the browser with `useEffect()`. In modern Next.js, you can fetch data directly on the server and send the rendered result to the client.**

I'll explain this from basic → intermediate → advanced.

---

# 1. What is Data Fetching?

Suppose your backend has:

```text
GET https://api.example.com/products
```

and returns:

```json
[
  {
    "id": 1,
    "name": "Laptop",
    "price": 800
  },
  {
    "id": 2,
    "name": "Phone",
    "price": 500
  }
]
```

Your Next.js application needs to:

1. Request the data
2. Receive the response
3. Convert it to JavaScript data
4. Render it in the UI

There are several places where this fetching can happen.

### Main approaches

| Approach                   | Runs where?   | Typical use                                    |
| -------------------------- | ------------- | ---------------------------------------------- |
| Server Component `fetch()` | Server        | Pages/data that don't need browser interaction |
| Client `fetch()`           | Browser       | Interactive/live client-side data              |
| Server Action              | Server        | Mutations/forms                                |
| Route Handler              | Server        | Creating your own API endpoint                 |
| Database query             | Server        | Direct database access                         |
| Third-party library        | Client/Server | Complex client-side fetching                   |

# 2. React vs Next.js Data Fetching

In a normal React application, you might write:

```jsx
"use client";

import { useEffect, useState } from "react";

export default function Products() {
  const [products, setProducts] = useState([]);

  useEffect(() => {
    fetch("/api/products")
      .then(res => res.json())
      .then(data => setProducts(data));
  }, []);

  return (
    <div>
      {products.map(product => (
        <p key={product.id}>{product.name}</p>
      ))}
    </div>
  );
}
```

The sequence is:

```text
Browser
   ↓
Render React page
   ↓
useEffect()
   ↓
API request
   ↓
Server
   ↓
Data
   ↓
setState()
   ↓
Re-render
```

This means the user may initially see:

```text
Loading...
```

Then the data appears.

# 3. Next.js Server Component Fetching

With the App Router, you can fetch directly inside a Server Component.

For example:

```jsx
export default async function Products() {
  const response = await fetch(
    "https://api.example.com/products"
  );

  const products = await response.json();

  return (
    <div>
      {products.map(product => (
        <p key={product.id}>
          {product.name}
        </p>
      ))}
    </div>
  );
}
```

Notice something important:

```jsx
export default async function Products()
```

The component itself is `async`.

You can therefore use:

```jsx
await fetch(...)
```

directly.

---

# 4. Why Can Next.js Do This?

Because the component is running on the **server**.

The browser doesn't execute this:

```jsx
const response = await fetch("https://api.example.com/products");
```

Instead:

```text
                    Next.js Server
                         │
                         │ fetch()
                         ↓
                 External API
                         │
                         ↓
                       Data
                         │
                         ↓
                 React rendering
                         │
                         ↓
                     Browser
```

This has several benefits.

### Benefit 1 — Less client-side JavaScript

You don't necessarily need:

```jsx
useEffect
useState
```

for simple server-rendered data.

### Benefit 2 — Secrets stay on server

Suppose your API requires:

```env
API_SECRET=abc123
```

You don't want this secret sent to the browser.

Server-side fetching allows:

```js
const response = await fetch(
  "https://api.example.com/data",
  {
    headers: {
      Authorization: `Bearer ${process.env.API_SECRET}`
    }
  }
);
```

The secret remains on the server.

# 5. Server Components vs Client Components

This distinction is extremely important.

## Server Component

By default, files in the App Router are Server Components.

```jsx
export default async function Page() {
  const response = await fetch("https://api.example.com/users");

  const users = await response.json();

  return <div>...</div>;
}
```

You can:

* fetch data
* access databases
* access environment variables
* perform server-side operations

But you cannot use browser-only React features such as:

```jsx
useState()
useEffect()
```

---

# 6. Client Component

If you write:

```jsx
"use client";
```

the component becomes a Client Component.

Example:

```jsx
"use client";

import { useEffect, useState } from "react";

export default function Products() {
  const [products, setProducts] = useState([]);

  useEffect(() => {
    fetch("/api/products")
      .then(res => res.json())
      .then(data => setProducts(data));
  }, []);

  return <div>...</div>;
}
```

Now fetching happens in the browser.

---

# 7. When Should You Use Server Fetching?

Prefer server fetching when the data:

* doesn't require browser interaction
* is needed to render the page
* comes from a database/backend
* requires secret credentials
* can be fetched before rendering

For example:

```text
Product page
Blog page
User profile
Dashboard statistics
News page
Documentation page
```

---

# 8. When Should You Use Client Fetching?

Client-side fetching makes sense when the data depends heavily on browser interaction.

For example:

```text
Search suggestions
Live notifications
Infinite scrolling
Client-side filters
Real-time dashboards
Chat applications
Auto-refreshing data
```

Example:

```jsx
"use client";

import { useEffect, useState } from "react";

export default function Notifications() {
  const [notifications, setNotifications] = useState([]);

  useEffect(() => {
    async function loadNotifications() {
      const response = await fetch("/api/notifications");
      const data = await response.json();

      setNotifications(data);
    }

    loadNotifications();
  }, []);

  return (
    <div>
      {notifications.map(notification => (
        <p key={notification.id}>
          {notification.message}
        </p>
      ))}
    </div>
  );
}
```

# 9. Fetching From Your Own Backend

Suppose you're building:

```text
Next.js
   ↓
Node/Express
   ↓
MongoDB
```

Your backend might expose:

```text
GET /api/users
```

Then Next.js can request it.

```jsx
export default async function UsersPage() {
  const response = await fetch(
    "http://localhost:5000/api/users"
  );

  const users = await response.json();

  return (
    <div>
      {users.map(user => (
        <p key={user.id}>{user.name}</p>
      ))}
    </div>
  );
}
```

In production:

```text
Next.js Server
      ↓
Express API
      ↓
Database
```

---

# 10. Fetching Directly From a Database

One of the powerful things about Server Components is that you don't necessarily need to create an API endpoint just for your own frontend.

For example:

```text
Next.js Server Component
        ↓
PostgreSQL
```

You could have:

```js
import { db } from "@/lib/db";

export default async function UsersPage() {
  const users = await db.user.findMany();

  return (
    <div>
      {users.map(user => (
        <p key={user.id}>{user.name}</p>
      ))}
    </div>
  );
}
```

This is often preferable to:

```text
Next.js
 ↓
/api/users
 ↓
Database
```

when the API isn't needed by another client.

# 11. Error Handling

Never assume that `fetch()` automatically throws an error for HTTP errors.

For example:

```text
404
500
401
```

may still produce a Response object.

So you should check:

```jsx
export default async function Products() {
  const response = await fetch(
    "https://api.example.com/products"
  );

  if (!response.ok) {
    throw new Error("Failed to fetch products");
  }

  const products = await response.json();

  return (
    <div>
      {products.map(product => (
        <p key={product.id}>{product.name}</p>
      ))}
    </div>
  );
}
```
