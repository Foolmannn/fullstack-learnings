# Programmatic Navigation in Next.js

**Programmatic navigation** means navigating the user to another route **using JavaScript/TypeScript code**, instead of the user clicking a normal `<Link>`.

In modern Next.js using the **App Router**, you use:

```tsx
import { useRouter } from "next/navigation";
```

---

## 1. Why Programmatic Navigation?

Suppose you have a login page:

```text
/login
```

After the user successfully logs in, you want to automatically send them to:

```text
/dashboard
```

You don't want them to click a link.

Instead:

```text
Login
  ↓
API request
  ↓
Success
  ↓
router.push("/dashboard")
  ↓
/dashboard
```

That's **programmatic navigation**.

---

# 2. `useRouter()`

First import it:

```tsx
"use client";

import { useRouter } from "next/navigation";
```

Then create the router:

```tsx
const router = useRouter();
```

Now you can navigate:

```tsx
router.push("/dashboard");
```

### Complete example

```tsx
"use client";

import { useRouter } from "next/navigation";

export default function Login() {
  const router = useRouter();

  function handleLogin() {
    // Login logic...

    router.push("/dashboard");
  }

  return (
    <button onClick={handleLogin}>
      Login
    </button>
  );
}
```

When the button is clicked:

```text
/login
  ↓
handleLogin()
  ↓
router.push("/dashboard")
  ↓
/dashboard
```

---

# 3. `router.push()`

This is the most commonly used method.

```tsx
router.push("/about");
```

It navigates to `/about` and adds the navigation to the browser's history.

For example:

```text
/home
  ↓
router.push("/about")
  ↓
/about
```

The browser history contains:

```text
/home → /about
```

So pressing **Back** can take you back to `/home`.

---

# 4. Dynamic Navigation

Suppose you have:

```text
app/
└── products/
    └── [id]/
        └── page.tsx
```

You can navigate dynamically:

```tsx
const productId = 101;

router.push(`/products/${productId}`);
```

This takes the user to:

```text
/products/101
```

Another example:

```tsx
function handleProductClick(id: string) {
  router.push(`/products/${id}`);
}
```

Then:

```tsx
<button onClick={() => handleProductClick("123")}>
  View Product
</button>
```

navigates to:

```text
/products/123
```

---

# 5. Navigation with Search Parameters

You can also navigate with query parameters.

```tsx
router.push("/products?category=mobile");
```

The URL becomes:

```text
/products?category=mobile
```

You can dynamically construct it:

```tsx
const category = "mobile";

router.push(`/products?category=${category}`);
```

---

## Multiple Search Parameters

```tsx
router.push(
  "/products?category=mobile&sort=price&page=2"
);
```

Result:

```text
/products
    ?category=mobile
    &sort=price
    &page=2
```

For more complex URLs, `URLSearchParams` is cleaner:

```tsx
const params = new URLSearchParams();

params.set("category", "mobile");
params.set("sort", "price");
params.set("page", "2");

router.push(`/products?${params.toString()}`);
```

---

# 6. `router.replace()`

Another important method is:

```tsx
router.replace("/dashboard");
```

The difference between `push()` and `replace()` is **browser history**.

### `push()`

```tsx
router.push("/dashboard");
```

History:

```text
/login
   ↓
/dashboard
```

Press Back:

```text
/dashboard
      ↓ Back
/login
```

### `replace()`

```tsx
router.replace("/dashboard");
```

History effectively becomes:

```text
/dashboard
```

The `/login` entry is replaced.

So:

> Use `replace()` when you don't want the user to return to the previous route using Back.

A common example is authentication:

```tsx
if (loginSuccessful) {
  router.replace("/dashboard");
}
```

---

# 7. `router.back()`

You can programmatically go back:

```tsx
router.back();
```

Example:

```tsx
"use client";

import { useRouter } from "next/navigation";

export default function ProductPage() {
  const router = useRouter();

  return (
    <button onClick={() => router.back()}>
      Go Back
    </button>
  );
}
```

This behaves similarly to clicking the browser's Back button.

---

# 8. `router.forward()`

You can also go forward:

```tsx
router.forward();
```

Example:

```tsx
<button onClick={() => router.forward()}>
  Go Forward
</button>
```

---

# 9. `router.refresh()`

Another method is:

```tsx
router.refresh();
```

This refreshes the current route's Server Component data.

For example:

```tsx
"use client";

import { useRouter } from "next/navigation";

export default function RefreshButton() {
  const router = useRouter();

  return (
    <button onClick={() => router.refresh()}>
      Refresh
    </button>
  );
}
```

This is useful after a mutation:

```text
Delete product
      ↓
Database updated
      ↓
router.refresh()
      ↓
Fresh server data
```

It isn't the same as doing a full browser reload.

---

# 10. Example: Form Submission

Programmatic navigation is very common after forms.

```tsx
"use client";

import { useRouter } from "next/navigation";

export default function Register() {
  const router = useRouter();

  async function handleSubmit(
    e: React.FormEvent<HTMLFormElement>
  ) {
    e.preventDefault();

    const response = await fetch("/api/register", {
      method: "POST",
    });

    if (response.ok) {
      router.push("/login");
    }
  }

  return (
    <form onSubmit={handleSubmit}>
      <button type="submit">
        Register
      </button>
    </form>
  );
}
```

Flow:

```text
User submits form
       ↓
API request
       ↓
Registration successful
       ↓
router.push("/login")
       ↓
/login
```

---

# 11. Example: Login

This is probably the most common real-world example.

```tsx
"use client";

import { useRouter } from "next/navigation";

export default function Login() {
  const router = useRouter();

  async function handleLogin() {
    const response = await fetch("/api/login", {
      method: "POST",
    });

    if (response.ok) {
      router.replace("/dashboard");
    }
  }

  return (
    <button onClick={handleLogin}>
      Login
    </button>
  );
}
```

Why `replace()`?

Because after successful login, you generally don't want:

```text
/dashboard
     ↓ Back
/login
```

to be the user's normal navigation path.

# 12. Example: Product Selection

Suppose you have:

```tsx
const products = [
  { id: 1, name: "Laptop" },
  { id: 2, name: "Phone" },
  { id: 3, name: "Tablet" },
];
```

You can navigate based on which product the user selects:

```tsx
"use client";

import { useRouter } from "next/navigation";

export default function Products() {
  const router = useRouter();

  function viewProduct(id: number) {
    router.push(`/products/${id}`);
  }

  return (
    <div>
      {products.map((product) => (
        <button
          key={product.id}
          onClick={() => viewProduct(product.id)}
        >
          {product.name}
        </button>
      ))}
    </div>
  );
}
```

Clicking:

```text
Laptop
```

could navigate to:

```text
/products/1
```

while:

```text
Phone
```

navigates to:

```text
/products/2
```

---

# 13. `useRouter()` Must Be in a Client Component

This is very important.

You **cannot** use:

```tsx
useRouter()
```

inside a Server Component.

You need:

```tsx
"use client";
```

at the top:

```tsx
"use client";

import { useRouter } from "next/navigation";
```

Why?

Because `useRouter()` is a **React client-side hook**.

---

# 14. Don't Confuse `next/router` and `next/navigation`

If you're using the **App Router**:

```text
app/
```

use:

```tsx
import { useRouter } from "next/navigation";
```

If you're using the older **Pages Router**:

```text
pages/
```

you'll see:

```tsx
import { useRouter } from "next/router";
```

### Modern App Router

```tsx
"use client";

import { useRouter } from "next/navigation";

const router = useRouter();

router.push("/dashboard");
```

### Pages Router

```tsx
import { useRouter } from "next/router";

const router = useRouter();

router.push("/dashboard");
```

Since you're learning modern Next.js and the `app/` directory, focus on **`next/navigation`**.

# 15. `<Link>` vs `useRouter()`

This is an important interview/conceptual distinction.

### `<Link>`

Use when the user should **click a link**.

```tsx
import Link from "next/link";

<Link href="/products">
  Products
</Link>
```

### `useRouter()`

Use when **your code decides when navigation should happen**.

```tsx
if (success) {
  router.push("/success");
}
```

Think:

```text
             Navigation
                 │
       ┌─────────┴─────────┐
       │                   │
     <Link>            useRouter()
       │                   │
  User clicks          Code decides
       │                   │
       ↓                   ↓
   /products          /dashboard
```

---

# 16. The Five Methods to Remember

For modern Next.js:

```tsx
const router = useRouter();
```

### Navigate

```tsx
router.push("/dashboard");
```

### Navigate without keeping current history entry

```tsx
router.replace("/dashboard");
```

### Go backward

```tsx
router.back();
```

### Go forward

```tsx
router.forward();
```

### Refresh current route data

```tsx
router.refresh();
```

## Final Mental Model

If your URL is:

```text
/products/123?category=mobile
```

then:

```text
                    URL
                     │
          ┌──────────┴──────────┐
          │                     │
       /products/123       ?category=mobile
          │                     │
       params              searchParams
```

And if you want to **change the URL from your code**:

```tsx
const router = useRouter();

router.push("/products/123");
```

So the core distinction is:

> **`params` → read dynamic route values**
> **`searchParams` → read query-string values**
> **`useRouter()` → programmatically navigate/change the route**
> **`<Link>` → declarative user navigation**


Yes. In Next.js, there are **several ways to navigate or redirect**, and choosing the right one depends on whether you're in a **Server Component, Client Component, Route Handler, or Middleware/Proxy**.

The important APIs are:

```text
<Link />
router.push()
router.replace()
redirect()
permanentRedirect()
useRouter()
```

Let's separate them clearly.

---

# 1. `redirect()`

`redirect()` is extremely useful in the **App Router**.

Import:

```tsx
import { redirect } from "next/navigation";
```

Then:

```tsx
redirect("/login");
```

For example, in a Server Component:

```tsx
import { redirect } from "next/navigation";

export default async function Dashboard() {
  const user = null;

  if (!user) {
    redirect("/login");
  }

  return <h1>Dashboard</h1>;
}
```

The flow is:

```text
/dashboard
     ↓
Check authentication
     ↓
User not logged in
     ↓
redirect("/login")
     ↓
/login
```

---

# 2. `redirect()` vs `router.push()`

This is one of the most important distinctions.

### `redirect()`

```tsx
redirect("/login");
```

Usually used on the **server**.

### `router.push()`

```tsx
router.push("/login");
```

Used in a **Client Component**.

```text
              Navigation
                   │
          ┌────────┴────────┐
          │                 │
       Server            Client
          │                 │
     redirect()        router.push()
```

---

# 3. Authentication Example

Suppose you have:

```text
app/
└── dashboard/
    └── page.tsx
```

You can protect it:

```tsx
import { redirect } from "next/navigation";

export default async function Dashboard() {
  const user = await getUser();

  if (!user) {
    redirect("/login");
  }

  return (
    <h1>
      Welcome to Dashboard
    </h1>
  );
}
```

This is a very common pattern.

The server checks:

```text
Is user authenticated?
        │
     ┌──┴──┐
     │     │
    Yes    No
     │     │
     ↓     ↓
Dashboard Login
```

---

# 4. `redirect()` Doesn't Return

This is a subtle point.

You can write:

```tsx
if (!user) {
  redirect("/login");
}

console.log("Hello");
```

You don't need:

```tsx
return redirect("/login");
```

In fact, conceptually `redirect()` interrupts the current rendering/action flow.

So normally:

```tsx
if (!user) {
  redirect("/login");
}
```

is enough.

---

# 5. `permanentRedirect()`

There is also:

```tsx
import { permanentRedirect } from "next/navigation";
```

Then:

```tsx
permanentRedirect("/new-url");
```

This represents a **permanent redirect**.

For example, suppose you moved:

```text
/products
```

to:

```text
/store
```

You could use:

```tsx
permanentRedirect("/store");
```

Conceptually:

```text
/products
    ↓
permanentRedirect()
    ↓
/store
```

Use this when the old URL has **permanently moved**.

---

# 6. `redirect()` vs `permanentRedirect()`

Think:

```text
redirect()
    ↓
Temporary / normal redirect

permanentRedirect()
    ↓
Permanent URL change
```

The underlying HTTP redirect status differs, which matters for browsers, caches, and search engines.

---

# 7. `router.push()`

For client-side programmatic navigation:

```tsx
"use client";

import { useRouter } from "next/navigation";

export default function Page() {
  const router = useRouter();

  return (
    <button onClick={() => router.push("/dashboard")}>
      Dashboard
    </button>
  );
}
```

Use it when some **client-side event or logic** triggers navigation.

Examples:

```text
Button click
Form submission
Successful API request
User selecting an item
Client-side condition
```

---

# 8. `router.replace()`

```tsx
router.replace("/dashboard");
```

Similar to `push()`, but doesn't create a new browser history entry.

Very common after login:

```tsx
if (loginSuccessful) {
  router.replace("/dashboard");
}
```

---

# 9. `<Link>`

For normal navigation, Next.js recommends the `Link` component.

```tsx
import Link from "next/link";

<Link href="/products">
  Products
</Link>
```

This is **declarative navigation**.

You tell Next.js:

> "This element links to `/products`."

Rather than:

> "When this JavaScript function runs, navigate to `/products`."

---

# 10. `router.back()`

You can programmatically go back:

```tsx
router.back();
```

Example:

```tsx
<button onClick={() => router.back()}>
  Back
</button>
```

---

# 11. `router.forward()`

Move forward in browser history:

```tsx
router.forward();
```

---

# 12. `router.refresh()`

Refresh the current route's server-rendered data:

```tsx
router.refresh();
```

Example:

```tsx
async function deleteProduct() {
  await fetch("/api/products/1", {
    method: "DELETE",
  });

  router.refresh();
}
```

Flow:

```text
Delete data
    ↓
Database changes
    ↓
router.refresh()
    ↓
Server Components fetch fresh data
```

---

# 13. Redirecting From a Server Action

This is another very important use case.

Suppose:

```tsx
"use server";

import { redirect } from "next/navigation";

export async function createPost(formData: FormData) {
  // Save post to database

  const postId = "123";

  redirect(`/posts/${postId}`);
}
```

After creating the post:

```text
Create Post
     ↓
Database
     ↓
Post created
     ↓
redirect(`/posts/123`)
     ↓
/posts/123
```

This is one of the strengths of the App Router.

---

# 14. Redirect After Form Submission

For example:

```tsx
import { redirect } from "next/navigation";

export async function createUser(formData: FormData) {
  const user = await createUserInDatabase(formData);

  redirect(`/users/${user.id}`);
}
```

After creation:

```text
/users/123
```

# 15. Redirect Based on Dynamic Params

Suppose:

```text
app/
└── products/
    └── [id]/
        └── page.tsx
```

You could do:

```tsx
import { redirect } from "next/navigation";

export default async function ProductPage({
  params,
}: {
  params: Promise<{ id: string }>;
}) {
  const { id } = await params;

  const product = await getProduct(id);

  if (!product) {
    redirect("/products");
  }

  return (
    <h1>
      {product.name}
    </h1>
  );
}
```

Flow:

```text
/products/123
      ↓
Find product 123
      ↓
 ┌────┴────┐
 │         │
Found    Not Found
 │         │
 ↓         ↓
Page    /products
```

# 16. `notFound()`

There's another very useful function:

```tsx
import { notFound } from "next/navigation";
```

Instead of:

```tsx
if (!product) {
  redirect("/products");
}
```

you can do:

```tsx
if (!product) {
  notFound();
}
```

This displays the route's **404 UI**.

Example:

```tsx
import { notFound } from "next/navigation";

export default async function ProductPage({
  params,
}: {
  params: Promise<{ id: string }>;
}) {
  const { id } = await params;

  const product = await getProduct(id);

  if (!product) {
    notFound();
  }

  return <h1>{product.name}</h1>;
}
```

This is usually more semantically correct when the requested resource doesn't exist.

---

# 17. `redirect()` vs `notFound()`

These have different meanings:

### `redirect()`

> "The user should go somewhere else."

```tsx
redirect("/login");
```

### `notFound()`

> "This requested resource doesn't exist."

```tsx
notFound();
```

For example:

```text
User not logged in
       ↓
redirect("/login")
```

while:

```text
Product ID 999 doesn't exist
       ↓
notFound()
       ↓
404
```

# 18. Full Navigation Toolkit

For the modern **App Router**, think of navigation like this:

```text
                 Next.js Navigation
                         │
       ┌─────────────────┼─────────────────┐
       │                 │                 │
     Link              Client            Server
       │                 │                 │
       ↓                 ↓                 ↓
   <Link />         useRouter()        redirect()
                         │              permanentRedirect()
                         │              notFound()
                         │
                  ┌──────┼──────┐
                  ↓      ↓      ↓
                push  replace  back
```

---

# 19. Which One Should You Use?

| Situation                                    | Use                   |
| -------------------------------------------- | --------------------- |
| Normal navigation link                       | `<Link>`              |
| Client-side button navigation                | `router.push()`       |
| Client-side navigation without history entry | `router.replace()`    |
| Go back                                      | `router.back()`       |
| Go forward                                   | `router.forward()`    |
| Refresh current server data                  | `router.refresh()`    |
| Server-side redirect                         | `redirect()`          |
| Permanent URL change                         | `permanentRedirect()` |
| Resource doesn't exist                       | `notFound()`          |

# 20. A Practical Example

Imagine a blog application.

### Normal navigation

```tsx
<Link href="/blog">
  Blog
</Link>
```

### User clicks "Read More"

```tsx
router.push(`/blog/${post.id}`);
```

### User isn't authenticated

```tsx
redirect("/login");
```

### User logs in

```tsx
router.replace("/dashboard");
```

### Post doesn't exist

```tsx
notFound();
```

### Post slug permanently changed

```tsx
permanentRedirect(`/blog/${newSlug}`);
```

So you can think of it as:

```text
                     Navigation
                         │
       ┌─────────────────┼──────────────────┐
       │                 │                  │
     Normal            Client             Server
       │                 │                  │
    <Link>          useRouter()         redirect()
                         │              permanentRedirect()
                         │              notFound()
                         │
                   push / replace
                   back / forward
                   refresh
```

**For modern Next.js App Router, these are the main navigation APIs you should know.** The especially important distinction is **`router.push/replace()` for client-side interaction vs `redirect()` for server-side control flow**.
