# `useRouter()` in Next.js — Programmatic Routing

In **Next.js App Router**, `useRouter()` lets you navigate the user to another route **from JavaScript/TypeScript code**.

The key idea is:

> **`<Link>` → navigation through a UI link**
> **`useRouter()` → navigation based on some logic/event**

For example, after login:

```text
User logs in
     ↓
Login successful
     ↓
router.push("/dashboard")
```

---

## 1. Import `useRouter`

With the App Router, import it from:

```tsx
import { useRouter } from "next/navigation";
```

Then:

```tsx
"use client";

import { useRouter } from "next/navigation";

export default function Login() {
  const router = useRouter();

  function handleLogin() {
    // login logic...

    router.push("/dashboard");
  }

  return (
    <button onClick={handleLogin}>
      Login
    </button>
  );
}
```

When the button is clicked:

```text
/login
   ↓
router.push("/dashboard")
   ↓
/dashboard
```

---

# 2. Why is it called "Programmatic Routing"?

Normally, you might navigate using:

```tsx
<Link href="/dashboard">
  Dashboard
</Link>
```

The user explicitly clicks a link.

With `useRouter()`:

```tsx
router.push("/dashboard");
```

**your JavaScript code decides when to navigate.**

For example:

```tsx
if (isAuthenticated) {
  router.push("/dashboard");
}
```

or:

```tsx
if (paymentSuccessful) {
  router.push("/success");
}
```

or:

```tsx
if (formSubmitted) {
  router.push("/thank-you");
}
```

That's programmatic navigation.

---

# 3. `router.push()`

The most commonly used method is:

```tsx
router.push("/dashboard");
```

It navigates to the specified route.

Example:

```tsx
"use client";

import { useRouter } from "next/navigation";

export default function Home() {
  const router = useRouter();

  return (
    <button onClick={() => router.push("/about")}>
      Go to About
    </button>
  );
}
```

Click:

```text
Go to About
     ↓
router.push("/about")
     ↓
/about
```

---

# 4. `push()` Adds a History Entry

This is an important concept.

Suppose you're currently at:

```text
/home
```

Then:

```tsx
router.push("/products");
```

Browser history becomes roughly:

```text
/home → /products
```

If the user presses the browser **Back** button:

```text
/products
     ↓ Back
/home
```

So:

> `push()` navigates **and adds a new browser history entry**.

---

# 5. `router.replace()`

`replace()` also navigates, but it **replaces the current history entry**.

```tsx
router.replace("/dashboard");
```

Suppose:

```text
/login
```

Then:

```tsx
router.replace("/dashboard");
```

History effectively becomes:

```text
/dashboard
```

rather than:

```text
/login → /dashboard
```

So pressing Back won't take the user back to `/login` from that replaced entry.

### Common use case

After authentication:

```tsx
if (loginSuccessful) {
  router.replace("/dashboard");
}
```

You often don't want:

```text
Dashboard
   ↓ Back
Login
```

because the user has already logged in.

---

# 6. `push()` vs `replace()`

| Method      | Navigates | Adds history | Back can return |
| ----------- | --------- | ------------ | --------------- |
| `push()`    | ✅         | ✅            | ✅               |
| `replace()` | ✅         | ❌            | ❌               |

Think:

```text
push()

/home
  ↓
/products
  ↓
/cart
```

History:

```text
/home
/products
/cart
```

Whereas:

```text
replace()

/home
  ↓ replace
/products
```

The `/home` entry is replaced.

---

# 7. `router.back()`

You can programmatically go back:

```tsx
router.back();
```

Equivalent conceptually to clicking the browser's Back button.

Example:

```tsx
"use client";

import { useRouter } from "next/navigation";

export default function ProductPage() {
  const router = useRouter();

  return (
    <button onClick={() => router.back()}>
      Go Back
    </button>
  );
}
```

---

# 8. `router.forward()`

You can also move forward in browser history:

```tsx
router.forward();
```

Example:

```tsx
<button onClick={() => router.forward()}>
  Forward
</button>
```

---

# 9. `router.refresh()`

This one is particularly useful in the App Router.

```tsx
router.refresh();
```

It tells Next.js to refresh the current route and request the latest server-rendered data.

For example:

```tsx
"use client";

import { useRouter } from "next/navigation";

export default function RefreshButton() {
  const router = useRouter();

  return (
    <button onClick={() => router.refresh()}>
      Refresh Data
    </button>
  );
}
```

It **doesn't mean a complete browser reload**.

Instead, Next.js can re-request the Server Component payload and update the UI while preserving appropriate client-side state.

---

# 10. `router.push()` with Dynamic Routes

Suppose you have:

```text
app/
└── products/
    └── [id]/
        └── page.tsx
```

You can navigate dynamically:

```tsx
router.push(`/products/${productId}`);
```

Example:

```tsx
"use client";

import { useRouter } from "next/navigation";

export default function ProductList() {
  const router = useRouter();

  const productId = 101;

  function viewProduct() {
    router.push(`/products/${productId}`);
  }

  return (
    <button onClick={viewProduct}>
      View Product
    </button>
  );
}
```

This navigates to:

```text
/products/101
```

And on the destination page:

```tsx
const { id } = await params;
```

gives:

```text
id = "101"
```

---

# 11. `useRouter()` with Search Parameters

You can also navigate to URLs containing query parameters.

```tsx
router.push("/products?category=mobile");
```

Or dynamically:

```tsx
const category = "mobile";

router.push(`/products?category=${category}`);
```

URL:

```text
/products?category=mobile
```

Then your Server Component can access it through:

```tsx
export default async function ProductsPage({
  searchParams,
}: {
  searchParams: Promise<{
    category?: string;
  }>;
}) {
  const { category } = await searchParams;

  return <h1>{category}</h1>;
}
```

---

# 12. Multiple Search Parameters

You could do:

```tsx
router.push(
  "/products?category=mobile&sort=price&page=2"
);
```

Result:

```text
/products
    ?category=mobile
    &sort=price
    &page=2
```

But for more complex query parameters, using `URLSearchParams` is cleaner.

```tsx
const params = new URLSearchParams();

params.set("category", "mobile");
params.set("sort", "price");
params.set("page", "2");

router.push(`/products?${params.toString()}`);
```

Result:

```text
/products?category=mobile&sort=price&page=2
```

---

# 13. Example: Search Box

Suppose you have:

```text
/products
```

and the user searches for:

```text
laptop
```

You could do:

```tsx
"use client";

import { useRouter } from "next/navigation";
import { useState } from "react";

export default function SearchBox() {
  const router = useRouter();
  const [search, setSearch] = useState("");

  function handleSearch() {
    router.push(
      `/products?search=${encodeURIComponent(search)}`
    );
  }

  return (
    <div>
      <input
        value={search}
        onChange={(e) => setSearch(e.target.value)}
        placeholder="Search products"
      />

      <button onClick={handleSearch}>
        Search
      </button>
    </div>
  );
}
```

If the user enters:

```text
laptop
```

then:

```tsx
router.push("/products?search=laptop");
```

The URL becomes:

```text
/products?search=laptop
```

---

# 14. Better Search Parameter Handling

For real applications, use `URLSearchParams`:

```tsx
function handleSearch() {
  const params = new URLSearchParams();

  params.set("search", search);

  router.push(`/products?${params.toString()}`);
}
```

This is especially useful when you have several filters:

```tsx
const params = new URLSearchParams();

params.set("search", search);
params.set("category", category);
params.set("sort", sort);
params.set("page", "1");

router.push(`/products?${params.toString()}`);
```

# 15. `router.push()` vs `<Link>`

This distinction is very important.

### Use `<Link>` for normal navigation

```tsx
import Link from "next/link";

<Link href="/products">
  Products
</Link>
```

Use this when the user is simply clicking something to navigate.

### Use `router.push()` for conditional/programmatic navigation

```tsx
if (isLoggedIn) {
  router.push("/dashboard");
}
```

Examples:

```text
Form submitted successfully
        ↓
router.push("/success")
```

```text
Payment successful
        ↓
router.push("/payment/success")
```

```text
Login successful
        ↓
router.replace("/dashboard")
```

```text
User clicks cancel
        ↓
router.back()
```

# 16. `useRouter()` Only Works in Client Components

This is extremely important.

You cannot do this in a normal Server Component:

```tsx
import { useRouter } from "next/navigation";
```

because `useRouter()` is a **Client Component hook**.

You need:

```tsx
"use client";
```

at the top:

```tsx
"use client";

import { useRouter } from "next/navigation";

export default function Button() {
  const router = useRouter();

  return (
    <button onClick={() => router.push("/dashboard")}>
      Dashboard
    </button>
  );
}
```

# 17. Common Authentication Example

This is one of the most practical uses.

```tsx
"use client";

import { useRouter } from "next/navigation";
import { useState } from "react";

export default function Login() {
  const router = useRouter();

  const [email, setEmail] = useState("");
  const [password, setPassword] = useState("");

  async function handleLogin() {
    const response = await fetch("/api/login", {
      method: "POST",
      body: JSON.stringify({
        email,
        password,
      }),
    });

    if (response.ok) {
      router.replace("/dashboard");
    }
  }

  return (
    <form
      onSubmit={(e) => {
        e.preventDefault();
        handleLogin();
      }}
    >
      <input
        value={email}
        onChange={(e) => setEmail(e.target.value)}
      />

      <input
        type="password"
        value={password}
        onChange={(e) => setPassword(e.target.value)}
      />

      <button type="submit">
        Login
      </button>
    </form>
  );
}
```

The flow:

```text
User submits login
        ↓
API request
        ↓
Login successful?
     /       \
   No         Yes
   ↓           ↓
error      router.replace()
               ↓
          /dashboard
```

# 18. `router.refresh()` After Mutation

Another useful pattern is:

```text
Create/update/delete data
        ↓
Server operation
        ↓
router.refresh()
        ↓
Server Component gets fresh data
```

For example:

```tsx
"use client";

import { useRouter } from "next/navigation";

export default function DeleteButton({
  id,
}: {
  id: string;
}) {
  const router = useRouter();

  async function handleDelete() {
    await fetch(`/api/products/${id}`, {
      method: "DELETE",
    });

    router.refresh();
  }

  return (
    <button onClick={handleDelete}>
      Delete
    </button>
  );
}
```

# 19. Complete `useRouter()` API

The main methods you should know are:

```tsx
const router = useRouter();
```

Then:

```tsx
router.push("/dashboard");
```

Navigate and **add history entry**.

```tsx
router.replace("/dashboard");
```

Navigate and **replace history entry**.

```tsx
router.back();
```

Go backward.

```tsx
router.forward();
```

Go forward.

```tsx
router.refresh();
```

Refresh the current route's server-rendered data.

# 20. `useRouter()` + Other Navigation Hooks

Next.js gives you several navigation tools:

```tsx
import {
  useRouter,
  usePathname,
  useSearchParams,
  useParams,
} from "next/navigation";
```

Think of them like this:

| Hook                | Purpose                       |
| ------------------- | ----------------------------- |
| `useRouter()`       | **Navigate** programmatically |
| `usePathname()`     | Get current pathname          |
| `useSearchParams()` | Get query parameters          |
| `useParams()`       | Get dynamic route parameters  |

Example URL:

```text
/products/123?category=mobile
```

You could have:

```tsx
const router = useRouter();
const pathname = usePathname();
const searchParams = useSearchParams();
const params = useParams();
```

Conceptually:

```text
URL
│
├── pathname
│      ↓
│   /products/123
│
├── params
│      ↓
│   { id: "123" }
│
├── searchParams
│      ↓
│   category=mobile
│
└── router
       ↓
   navigate somewhere
```

## The mental model to remember

```text
                 Next.js Navigation
                       │
          ┌────────────┴────────────┐
          │                         │
       <Link>                  useRouter()
          │                         │
     User clicks              Code decides
          │                         │
          ↓                         ↓
    /products              router.push(...)
                                  │
                                  ↓
                             /products
```

And the most important methods:

```tsx
router.push("/page");
```

**Go somewhere and keep current page in history.**

```tsx
router.replace("/page");
```

**Go somewhere without keeping the current page in that history entry.**

```tsx
router.back();
```

**Go back.**

```tsx
router.forward();
```

**Go forward.**

```tsx
router.refresh();
```

**Refresh the current route's server-rendered data.**

For your Next.js learning, the natural progression is **`Link` → `useRouter` → `usePathname` → `useSearchParams` → `useParams` → dynamic routes**, because these pieces work together constantly in real applications.
