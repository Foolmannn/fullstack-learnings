## File Colocation in Next.js

**File colocation** in Next.js means keeping files that belong to a particular route or feature **close together inside the same folder**, instead of putting every component, utility, or data file into a global folder.

This is especially useful with the **App Router** introduced in Next.js 13+.

### 1. Basic idea

Suppose you have a dashboard:

```text
app/
├── dashboard/
│   ├── page.tsx
│   ├── loading.tsx
│   ├── error.tsx
│   ├── DashboardHeader.tsx
│   ├── DashboardStats.tsx
│   ├── dashboard.css
│   └── utils.ts
│
├── products/
│   ├── page.tsx
│   ├── ProductCard.tsx
│   ├── ProductList.tsx
│   └── utils.ts
│
└── page.tsx
```

Here, everything related to `/dashboard` is colocated inside `dashboard/`.

The important point is:

> **Not every file inside `app` creates a route.**

Only special Next.js files such as `page.tsx`, `layout.tsx`, `route.ts`, etc. have routing meaning.

So:

```text
app/
└── dashboard/
    ├── page.tsx
    ├── DashboardStats.tsx
    ├── DashboardHeader.tsx
    └── utils.ts
```

creates:

```text
/dashboard
```

but:

```text
DashboardStats.tsx
DashboardHeader.tsx
utils.ts
```

do **not** become routes.

---

# 2. Why is this useful?

Without colocation, you might create:

```text
components/
├── DashboardHeader.tsx
├── DashboardStats.tsx
├── ProductCard.tsx
├── ProductList.tsx
├── UserProfile.tsx
└── ...

utils/
├── dashboardUtils.ts
├── productUtils.ts
└── ...

styles/
├── dashboard.css
├── product.css
└── ...
```

As the application grows, it becomes difficult to determine which files belong to which feature.

With colocation:

```text
app/
├── dashboard/
│   ├── page.tsx
│   ├── DashboardHeader.tsx
│   ├── DashboardStats.tsx
│   └── utils.ts
│
└── products/
    ├── page.tsx
    ├── ProductCard.tsx
    ├── ProductList.tsx
    └── utils.ts
```

The relationship is much clearer.

---

# 3. Colocation does NOT affect routing

Consider:

```text
app/
└── dashboard/
    ├── page.tsx
    ├── DashboardStats.tsx
    └── helpers.ts
```

Next.js sees:

```text
/dashboard/page.tsx
```

and creates:

```text
/dashboard
```

It does **not** create:

```text
/dashboard/DashboardStats
/dashboard/helpers
```

because those files aren't route files.

This gives you freedom to organize route-specific code inside the route folder.

# 4. Example with components

Suppose your dashboard contains:

```text
app/
└── dashboard/
    ├── page.tsx
    ├── DashboardHeader.tsx
    ├── StatsCard.tsx
    └── RecentTransactions.tsx
```

Your `page.tsx` could use them:

```tsx
import DashboardHeader from "./DashboardHeader";
import StatsCard from "./StatsCard";
import RecentTransactions from "./RecentTransactions";

export default function DashboardPage() {
  return (
    <main>
      <DashboardHeader />

      <StatsCard />

      <RecentTransactions />
    </main>
  );
}
```

Everything needed specifically by the dashboard is nearby.

# 5. Private folders — `_folder`

Next.js also provides a convention for making **private folders**.

A folder beginning with `_` is ignored by the routing system.

For example:

```text
app/
└── dashboard/
    ├── page.tsx
    └── _components/
        ├── DashboardHeader.tsx
        ├── StatsCard.tsx
        └── RecentTransactions.tsx
```

The `_components` folder is not treated as a route segment.

You can import:

```tsx
import DashboardHeader from "./_components/DashboardHeader";
```

This is useful when you want to make the intention very clear:

> "These files are implementation details of this route."

# 7. Route groups and colocation

You can also combine colocation with **route groups**.

A folder wrapped in parentheses is a route group:

```text
app/
├── (marketing)/
│   ├── page.tsx
│   ├── about/
│   │   └── page.tsx
│   └── contact/
│       └── page.tsx
│
└── (dashboard)/
    ├── dashboard/
    │   └── page.tsx
    └── settings/
        └── page.tsx
```

The `(marketing)` and `(dashboard)` folders **don't appear in the URL**.

So:

```text
app/(dashboard)/dashboard/page.tsx
```

produces:

```text
/dashboard
```

not:

```text
/(dashboard)/dashboard
```

This allows you to organize application sections without changing URLs.

# 8. Colocation vs global components

A useful rule is:

### Route-specific component

Keep it close to the route:

```text
app/
└── products/
    ├── page.tsx
    └── _components/
        ├── ProductCard.tsx
        └── ProductFilters.tsx
```

### Reusable across many routes

Put it in a shared location:

```text
components/
├── Button.tsx
├── Modal.tsx
├── Navbar.tsx
└── Input.tsx
```

For example:

```text
app/
├── dashboard/
│   └── _components/
│       └── ExpenseChart.tsx
│
├── expenses/
│   └── _components/
│       └── ExpenseForm.tsx
│
components/
├── Button.tsx
├── Modal.tsx
└── Navbar.tsx
```

The distinction is:

```text
Specific to one feature
        ↓
Colocate it

Used throughout application
        ↓
Shared components
```

# 9. Colocation with data fetching

You can also colocate data-related code.

For example:

```text
app/
└── products/
    ├── page.tsx
    ├── _components/
    │   ├── ProductCard.tsx
    │   └── ProductList.tsx
    │
    └── _lib/
        └── getProducts.ts
```

Then:

```tsx
// app/products/page.tsx

import { getProducts } from "./_lib/getProducts";
import ProductList from "./_components/ProductList";

export default async function ProductsPage() {
  const products = await getProducts();

  return <ProductList products={products} />;
}
```

This keeps product-specific data fetching close to the product route.

# 10. Colocation with Server Actions

This becomes particularly useful with Server Actions.

For example:

```text
app/
└── expenses/
    ├── page.tsx
    ├── _components/
    │   └── ExpenseForm.tsx
    │
    └── _actions/
        └── createExpense.ts
```

You might have:

```tsx
// _actions/createExpense.ts

"use server";

export async function createExpense(formData: FormData) {
  // database operation
}
```

And the form can import it:

```tsx
import { createExpense } from "../_actions/createExpense";
```

Now the action is clearly associated with the expenses feature.

# 11. A practical project structure

For a real Next.js application, you might use:

```text
src/
├── app/
│   ├── layout.tsx
│   ├── page.tsx
│   │
│   ├── dashboard/
│   │   ├── page.tsx
│   │   ├── loading.tsx
│   │   └── _components/
│   │       ├── Stats.tsx
│   │       ├── Chart.tsx
│   │       └── RecentActivity.tsx
│   │
│   ├── expenses/
│   │   ├── page.tsx
│   │   ├── _components/
│   │   │   ├── ExpenseForm.tsx
│   │   │   └── ExpenseList.tsx
│   │   └── _actions/
│   │       └── createExpense.ts
│   │
│   └── settings/
│       ├── page.tsx
│       └── _components/
│           └── SettingsForm.tsx
│
├── components/
│   ├── Navbar.tsx
│   ├── Sidebar.tsx
│   ├── Button.tsx
│   └── Modal.tsx
│
├── lib/
│   ├── db.ts
│   └── auth.ts
│
└── types/
    └── index.ts
```

This gives you a nice separation:

**`app/`**

→ routing + route-specific code

**`app/*/_components/`**

→ components belonging to a particular feature

**`components/`**

→ globally reusable UI

**`lib/`**

→ globally reusable infrastructure/utilities

**`types/`**

→ shared TypeScript types

## 12. The important distinction

Think of Next.js folders as having two purposes:

```text
                 Next.js folder
                      │
          ┌───────────┴───────────┐
          │                       │
     Route structure          Code organization
          │                       │
     page.tsx                 components
     layout.tsx               utilities
     loading.tsx              actions
     error.tsx                types
     route.ts                 etc.
```

**File colocation takes advantage of the fact that Next.js only gives routing meaning to specific special files.**

So you can safely keep supporting files next to your route without accidentally creating routes.

### In short

```text
app/
└── products/
    ├── page.tsx              ← /products
    ├── loading.tsx           ← loading UI
    ├── error.tsx             ← error UI
    ├── _components/          ← private implementation
    │   ├── ProductCard.tsx
    │   └── ProductList.tsx
    ├── _actions/
    │   └── createProduct.ts
    └── _lib/
        └── getProducts.ts
```

This is **file colocation**: keep code that belongs together **physically together**, while using Next.js's special-file conventions to control what actually becomes part of the routing system.
