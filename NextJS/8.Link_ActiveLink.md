# Links in Next.js — Detailed Guide

In Next.js, links are primarily handled using the **`<Link>` component** from `next/link`. It is one of the most important features for navigation because Next.js can navigate between pages **without performing a full browser refresh**.

---

## 1. Why use `<Link>` instead of `<a>`?

In normal HTML, you might write:

```html
<a href="/about">About</a>
```

This works, but clicking it normally causes the browser to request and reload the entire page.

In Next.js, you generally use:

```jsx
import Link from "next/link";

<Link href="/about">About</Link>
```

Next.js can perform **client-side navigation**, meaning it can change the route without completely reloading the browser page.

### Basic comparison

| HTML                            | Next.js                            |
| ------------------------------- | ---------------------------------- |
| `<a href="/about">About</a>`    | `<Link href="/about">About</Link>` |
| Full navigation/reload normally | Client-side navigation             |
| Browser handles navigation      | Next.js router handles navigation  |
| Basic HTML                      | Next.js optimized navigation       |

---

# 2. Basic `<Link>` syntax

```jsx
import Link from "next/link";

export default function Home() {
  return (
    <div>
      <Link href="/about">About Us</Link>
    </div>
  );
}
```

When the user clicks **About Us**, Next.js navigates to:

```text
/about
```

assuming you have an appropriate route.

For the App Router:

```text
app/
├── page.js
└── about/
    └── page.js
```

The URL becomes:

```text
http://localhost:3000/about
```

# 3. Creating navigation menus

A common use of `Link` is a navbar.

```jsx
import Link from "next/link";

export default function Navbar() {
  return (
    <nav>
      <Link href="/">Home</Link>
      <Link href="/about">About</Link>
      <Link href="/products">Products</Link>
      <Link href="/contact">Contact</Link>
    </nav>
  );
}
```

You can style these with Tailwind:

```jsx
<nav className="flex gap-6">
  <Link href="/">Home</Link>
  <Link href="/about">About</Link>
  <Link href="/products">Products</Link>
  <Link href="/contact">Contact</Link>
</nav>
```

# 4. Linking to nested routes

Suppose your project contains:

```text
app/
├── page.js
├── products/
│   ├── page.js
│   └── books/
│       └── page.js
```

You can navigate to `/products`:

```jsx
<Link href="/products">
  Products
</Link>
```

And `/products/books`:

```jsx
<Link href="/products/books">
  Books
</Link>
```

---

# 5. Dynamic routes

This is particularly important in Next.js.

Suppose you have:

```text
app/
└── products/
    └── [id]/
        └── page.js
```

This represents URLs such as:

```text
/products/1
/products/2
/products/100
```

You can dynamically construct the URL:

```jsx
<Link href={`/products/${product.id}`}>
  View Product
</Link>
```

For example:

```jsx
const product = {
  id: 42,
  name: "Laptop"
};

<Link href={`/products/${product.id}`}>
  {product.name}
</Link>
```

The resulting link is:

```text
/products/42
```

---

# 6. Dynamic routes with multiple parameters

Suppose your structure is:

```text
app/
└── blog/
    └── [category]/
        └── [id]/
            └── page.js
```

You could have:

```text
/blog/technology/25
/blog/sports/10
```

Then:

```jsx
<Link href={`/blog/${category}/${id}`}>
  Read Article
</Link>
```

For example:

```jsx
<Link href="/blog/technology/25">
  Read Article
</Link>
```

---

# 7. Linking with query parameters

You can include query parameters directly:

```jsx
<Link href="/products?category=books">
  Books
</Link>
```

This generates:

```text
/products?category=books
```

Multiple parameters:

```jsx
<Link href="/products?category=books&sort=price">
  Books sorted by price
</Link>
```

URL:

```text
/products?category=books&sort=price
```

---

# 8. Using an object for `href`

Next.js also supports an object form of `href`.

```jsx
<Link
  href={{
    pathname: "/products",
    query: {
      category: "books",
      sort: "price"
    }
  }}
>
  Books
</Link>
```

This produces a URL similar to:

```text
/products?category=books&sort=price
```

This approach is particularly useful when constructing URLs programmatically.

---

# 9. Linking to external websites

`Link` is primarily useful for **internal Next.js navigation**.

For an external website, normal `<a>` is generally appropriate:

```jsx
<a href="https://example.com">
  Visit Example
</a>
```

For example:

```jsx
<a
  href="https://github.com"
  target="_blank"
  rel="noopener noreferrer"
>
  GitHub
</a>
```

### Rule of thumb

```text
Internal route
     ↓
<Link>

External website
     ↓
<a>
```

# 10. Linking to files

Suppose you have:

```text
public/
└── resume.pdf
```

You can link to it using:

```jsx
<a href="/resume.pdf" target="_blank">
  Download Resume
</a>
```

You don't normally need `<Link>` for static files.

For downloading:

```jsx
<a href="/resume.pdf" download>
  Download Resume
</a>
```

# 11. Link with an image

You can put an image inside `Link`.

```jsx
import Link from "next/link";
import Image from "next/image";

export default function Logo() {
  return (
    <Link href="/">
      <Image
        src="/logo.png"
        alt="Logo"
        width={120}
        height={40}
      />
    </Link>
  );
}
```

Clicking the logo takes the user to `/`.

This is very common in navigation bars.

---

# 12. Link with buttons

You can visually style a `Link` to look like a button:

```jsx
<Link
  href="/login"
  className="rounded bg-blue-600 px-4 py-2 text-white"
>
  Login
</Link>
```

The important idea is:

> A `Link` can look like a button, but semantically it is still a link.

If the action is actually something like **submit**, **delete**, or **toggle**, use a `<button>` instead.

# 13. Active navigation links

A common requirement is highlighting the current page.

For example:

```text
Home
Products
About
```

If the user is currently on:

```text
/products
```

you may want:

```text
Home
Products  ← highlighted
About
```

You can use `usePathname()`.

```jsx
"use client";

import Link from "next/link";
import { usePathname } from "next/navigation";

export default function Navbar() {
  const pathname = usePathname();

  return (
    <nav className="flex gap-4">
      <Link
        href="/"
        className={pathname === "/" ? "font-bold" : ""}
      >
        Home
      </Link>

      <Link
        href="/products"
        className={pathname === "/products" ? "font-bold" : ""}
      >
        Products
      </Link>

      <Link
        href="/about"
        className={pathname === "/about" ? "font-bold" : ""}
      >
        About
      </Link>
    </nav>
  );
}
```

Notice that this component needs:

```jsx
"use client";
```

because `usePathname()` is a client-side hook.

---

# 14. Active link with Tailwind

You can make it more visually useful:

```jsx
<Link
  href="/products"
  className={
    pathname === "/products"
      ? "text-blue-600 font-semibold"
      : "text-gray-600"
  }
>
  Products
</Link>
```

Or:

```jsx
className={`px-3 py-2 rounded ${
  pathname === "/products"
    ? "bg-blue-600 text-white"
    : "text-gray-600"
}`}
```

# 15. Active link for nested routes

Suppose you want `/products` to remain active for:

```text
/products
/products/books
/products/electronics
/products/123
```

Instead of:

```jsx
pathname === "/products"
```

you can use:

```jsx
pathname.startsWith("/products")
```

Example:

```jsx
<Link
  href="/products"
  className={
    pathname.startsWith("/products")
      ? "font-bold text-blue-600"
      : "text-gray-600"
  }
>
  Products
</Link>
```

This is useful for dashboard sidebars.

---

# 16. `replace` prop

Normally, when you navigate:

```jsx
<Link href="/about">
  About
</Link>
```

Next.js adds `/about` to the browser history.

So:

```text
Home
 ↓
About
 ↓
Contact
```

The Back button can take you back through those pages.

With:

```jsx
<Link href="/about" replace>
  About
</Link>
```

the current history entry is replaced.

This is useful when you don't want the user to return to the previous route through browser Back navigation.

---

# 17. `scroll` prop

By default, Next.js manages scrolling during navigation.

You can control this:

```jsx
<Link
  href="/about"
  scroll={false}
>
  About
</Link>
```

`scroll={false}` prevents the normal scroll-to-top behavior during navigation.

This can be useful for certain interfaces where maintaining the current scroll position is desirable.

---

# 18. `prefetch`

One of the important performance features of Next.js navigation is **prefetching**.

Example:

```jsx
<Link href="/dashboard">
  Dashboard
</Link>
```

Next.js can prefetch the destination route when appropriate, allowing navigation to feel faster.

You can explicitly control this:

```jsx
<Link
  href="/dashboard"
  prefetch={false}
>
  Dashboard
</Link>
```

This disables automatic prefetching for that link.

### Why is prefetching useful?

Imagine:

```text
User sees page
       ↓
Next.js prefetches destination
       ↓
User clicks link
       ↓
Navigation can be faster
```

You generally don't need to manually configure this unless you have a specific reason.

# 19. `Link` and layouts

This becomes particularly useful with the **App Router**.

Suppose:

```text
app/
├── layout.js
├── page.js
├── about/
│   └── page.js
└── dashboard/
    ├── layout.js
    ├── page.js
    └── settings/
        └── page.js
```

Your main layout could contain:

```jsx
import Link from "next/link";

export default function RootLayout({ children }) {
  return (
    <html lang="en">
      <body>
        <nav>
          <Link href="/">Home</Link>
          <Link href="/about">About</Link>
          <Link href="/dashboard">Dashboard</Link>
        </nav>

        {children}
      </body>
    </html>
  );
}
```

When navigating between pages, Next.js can preserve layouts while changing the relevant route content.

This is one of the major advantages of the App Router architecture.

# 20. `Link` vs `useRouter()`

This is an important distinction.

### Use `Link` for navigation initiated by the user

```jsx
<Link href="/dashboard">
  Dashboard
</Link>
```

### Use `useRouter()` when navigation needs to happen programmatically

For example:

```jsx
"use client";

import { useRouter } from "next/navigation";

export default function Login() {
  const router = useRouter();

  function handleLogin() {
    // Login logic

    router.push("/dashboard");
  }

  return (
    <button onClick={handleLogin}>
      Login
    </button>
  );
}
```

So:

```text
User clicks a navigation link
        ↓
<Link>
```

while:

```text
Something happens in JavaScript
        ↓
router.push()
```

---

# 21. `router.push()`

You can navigate programmatically:

```jsx
router.push("/dashboard");
```

With query parameters:

```jsx
router.push("/products?category=books");
```

Dynamic route:

```jsx
router.push(`/products/${id}`);
```

---

# 22. `router.replace()`

Similar to `<Link replace>`:

```jsx
router.replace("/dashboard");
```

The current history entry is replaced.

This is commonly useful after authentication:

```jsx
router.replace("/dashboard");
```

so the user doesn't easily navigate back to the login page using browser history.

---

# 23. `router.back()`

You can go back:

```jsx
router.back();
```

For example:

```jsx
<button onClick={() => router.back()}>
  Go Back
</button>
```

---

# 24. `router.forward()`

You can also move forward in browser history:

```jsx
router.forward();
```

---

# 25. `router.refresh()`

In the App Router:

```jsx
router.refresh();
```

This tells Next.js to refresh the current route's server-rendered data without performing a full browser reload.

For example, after an operation that changes server-side data, you may use:

```jsx
router.refresh();
```

---

# 26. `Link` and Server Components

One thing that can confuse beginners is that **you can use `<Link>` inside Server Components**.

For example:

```jsx
import Link from "next/link";

export default function Page() {
  return (
    <Link href="/about">
      About
    </Link>
  );
}
```

You don't need:

```jsx
"use client";
```

just because you're using `Link`.

However, hooks such as:

```jsx
usePathname()
useRouter()
```

require a Client Component.

# 30. URL encoding

When constructing URLs from arbitrary user input, you should consider URL encoding.

For example:

```jsx
const search = "gaming laptop";
```

Instead of manually concatenating potentially complex values, you can use `URLSearchParams`:

```jsx
const params = new URLSearchParams({
  q: search,
  sort: "price"
});

<Link href={`/products?${params.toString()}`}>
  Search
</Link>
```

Result:

```text
/products?q=gaming+laptop&sort=price
```

This is particularly useful for search/filter interfaces.

# 31. Linking to hash fragments

You can link to a particular section of a page:

```jsx
<Link href="/about#team">
  Our Team
</Link>
```

This navigates to:

```text
/about#team
```

Your page could have:

```jsx
<section id="team">
  <h2>Our Team</h2>
</section>
```

You can also use:

```jsx
<a href="#team">
  Our Team
</a>
```

when you're already on the same page.

# 32. `Link` and SEO

Links are extremely important for SEO.

A properly structured website should have meaningful internal links:

```jsx
<Link href="/blog/nextjs">
  Learn Next.js
</Link>
```

rather than meaningless links such as:

```jsx
<Link href="/blog/nextjs">
  Click here
</Link>
```

Descriptive link text helps users and search engines understand the destination.

A good structure might look like:

```text
Home
 ├── Products
 │    ├── Laptops
 │    ├── Phones
 │    └── Accessories
 │
 ├── Blog
 │    ├── Next.js
 │    └── React
 │
 └── About
```

# 33. Common mistake: using `<a>` everywhere

You might write:

```jsx
<a href="/dashboard">
  Dashboard
</a>
```

This isn't necessarily invalid, but for normal internal Next.js navigation, prefer:

```jsx
<Link href="/dashboard">
  Dashboard
</Link>
```

This allows Next.js to provide its routing behavior and optimizations.

---

# 34. Common mistake: using `<Link>` for external URLs

Don't generally do:

```jsx
<Link href="https://google.com">
  Google
</Link>
```

Prefer:

```jsx
<a href="https://google.com">
  Google
</a>
```

`Link` is primarily designed around your application's routes.

---

# 35. Common mistake: using `router.push()` for ordinary navigation

You don't need:

```jsx
<button onClick={() => router.push("/about")}>
  About
</button>
```

if all you're doing is providing a normal navigation link.

Prefer:

```jsx
<Link href="/about">
  About
</Link>
```

Use `router.push()` when navigation depends on some programmatic logic.

# 37. Practical example: complete navbar

```jsx
"use client";

import Link from "next/link";
import { usePathname } from "next/navigation";

export default function Navbar() {
  const pathname = usePathname();

  const links = [
    {
      name: "Home",
      href: "/"
    },
    {
      name: "Products",
      href: "/products"
    },
    {
      name: "About",
      href: "/about"
    },
    {
      name: "Contact",
      href: "/contact"
    }
  ];

  return (
    <nav className="flex gap-6 p-4">

      {links.map((link) => {
        const active =
          link.href === "/"
            ? pathname === "/"
            : pathname.startsWith(link.href);

        return (
          <Link
            key={link.href}
            href={link.href}
            className={
              active
                ? "font-bold text-blue-600"
                : "text-gray-600"
            }
          >
            {link.name}
          </Link>
        );
      })}

    </nav>
  );
}
```

This pattern is very useful for real applications.

# 38. Important Next.js navigation APIs

For modern Next.js App Router development, remember these:

| Feature             | Purpose                               |
| ------------------- | ------------------------------------- |
| `<Link>`            | Normal internal navigation            |
| `<a>`               | External links/static resources       |
| `useRouter()`       | Programmatic navigation               |
| `router.push()`     | Navigate to a route                   |
| `router.replace()`  | Navigate without adding history entry |
| `router.back()`     | Go back                               |
| `router.forward()`  | Go forward                            |
| `router.refresh()`  | Refresh current route's server data   |
| `usePathname()`     | Get current pathname                  |
| `useSearchParams()` | Read URL query parameters             |

---

## 39. The most important distinction

As you're learning Next.js, this is the rule I'd recommend memorizing:

### Normal internal navigation

```jsx
<Link href="/about">
  About
</Link>
```

### External website

```jsx
<a href="https://example.com">
  Example
</a>
```

### Navigation after some JavaScript logic

```jsx
"use client";

import { useRouter } from "next/navigation";

const router = useRouter();

router.push("/dashboard");
```

### Reading the current URL

```jsx
"use client";

import { usePathname } from "next/navigation";

const pathname = usePathname();
```

### Reading query parameters

```jsx
"use client";

import { useSearchParams } from "next/navigation";

const searchParams = useSearchParams();

const query = searchParams.get("q");
```

## Final mental model

Think of Next.js navigation like this:

```text
                         NEXT.JS NAVIGATION
                                │
              ┌─────────────────┼─────────────────┐
              │                 │                 │
         User navigation   External link    Programmatic
              │                 │                 │
            <Link>              <a>          useRouter()
              │                                   │
       ┌──────┴──────┐                    ┌───────┼────────┐
       │             │                    │       │        │
    Static       Dynamic               push()  replace()  back()
    route        route
       │             │
   /about       /products/123
```

**For most internal links in a Next.js application, start with `<Link>`.** It is the standard, declarative way to navigate between routes, while `useRouter()` is for cases where navigation needs to be triggered by application logic.
