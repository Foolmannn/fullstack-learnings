In **Next.js App Router**, `params` and `searchParams` are two important ways to get information from the URL.

The easiest way to remember them is:

> **`params` → dynamic path values**
> **`searchParams` → query-string values**

For example:

```text
/products/123?category=electronics&sort=price
```

* `123` → **params**
* `category=electronics` and `sort=price` → **searchParams**

---

# 1. `params` in Next.js

`params` is used when you have a **dynamic route segment**.

Suppose your folder structure is:

```text
app/
└── products/
    └── [id]/
        └── page.tsx
```

The `[id]` is a dynamic route segment.

Now if the user visits:

```text
/products/123
```

Then `id` is available through `params`.

### Example

```tsx
export default async function ProductPage({
  params,
}: {
  params: Promise<{ id: string }>
}) {
  const { id } = await params;

  return (
    <div>
      Product ID: {id}
    </div>
  );
}
```

Visiting:

```text
/products/123
```

gives:

```text
Product ID: 123
```

### Important

In current Next.js App Router versions, `params` is asynchronous, so you commonly use:

```tsx
const { id } = await params;
```

rather than treating `params` as a plain object.

---

# 2. Multiple Dynamic Parameters

You can have multiple dynamic segments.

Folder structure:

```text
app/
└── products/
    └── [category]/
        └── [id]/
            └── page.tsx
```

URL:

```text
/products/electronics/123
```

You can access both:

```tsx
export default async function ProductPage({
  params,
}: {
  params: Promise<{
    category: string;
    id: string;
  }>
}) {
  const { category, id } = await params;

  return (
    <>
      <p>Category: {category}</p>
      <p>ID: {id}</p>
    </>
  );
}
```

Result:

```text
Category: electronics
ID: 123
```

---

# 3. `searchParams`

`searchParams` represents the **query string** after `?`.

For example:

```text
/products?category=electronics&sort=price
```

Here:

```text
category=electronics
sort=price
```

are search parameters.

For a page:

```tsx
export default async function ProductsPage({
  searchParams,
}: {
  searchParams: Promise<{
    category?: string;
    sort?: string;
  }>
}) {
  const params = await searchParams;

  return (
    <>
      <p>Category: {params.category}</p>
      <p>Sort: {params.sort}</p>
    </>
  );
}
```

URL:

```text
/products?category=electronics&sort=price
```

Result:

```text
Category: electronics
Sort: price
```

---

# 4. `params` vs `searchParams`

This is the most important distinction.

Consider:

```text
/products/123?category=electronics&sort=price
```

Your folder:

```text
app/
└── products/
    └── [id]/
        └── page.tsx
```

Then:

```tsx
export default async function ProductPage({
  params,
  searchParams,
}: {
  params: Promise<{ id: string }>;
  searchParams: Promise<{
    category?: string;
    sort?: string;
  }>;
}) {
  const { id } = await params;
  const { category, sort } = await searchParams;

  return (
    <div>
      <p>ID: {id}</p>
      <p>Category: {category}</p>
      <p>Sort: {sort}</p>
    </div>
  );
}
```

The URL:

```text
/products/123?category=electronics&sort=price
```

produces:

```text
id        → 123
category  → electronics
sort      → price
```

### Think of it like this:

```text
/products/123?category=electronics&sort=price
          │                       │
          │                       └── searchParams
          │
          └── params
```

---

# 5. Dynamic Route `[id]`

The most common use of `params` is fetching a particular resource.

For example:

```text
app/
└── users/
    └── [id]/
        └── page.tsx
```

URL:

```text
/users/45
```

Code:

```tsx
export default async function UserPage({
  params,
}: {
  params: Promise<{ id: string }>
}) {
  const { id } = await params;

  const response = await fetch(
    `https://api.example.com/users/${id}`
  );

  const user = await response.json();

  return (
    <div>
      <h1>{user.name}</h1>
    </div>
  );
}
```

Here `params` determines **which user** you're displaying.

# 6. Search Params for Filtering

`searchParams` is particularly useful for filtering.

For example:

```text
/products?category=mobile&brand=samsung
```

You could do:

```tsx
export default async function ProductsPage({
  searchParams,
}: {
  searchParams: Promise<{
    category?: string;
    brand?: string;
  }>
}) {
  const { category, brand } = await searchParams;

  return (
    <div>
      <p>Category: {category}</p>
      <p>Brand: {brand}</p>
    </div>
  );
}
```

This is commonly used for:

* filtering
* sorting
* searching
* pagination
* tabs
* price ranges
* category selection

For example:

```text
/products?search=laptop
/products?category=mobile
/products?sort=price-low
/products?page=2
/products?minPrice=500&maxPrice=2000
```

# 7. Search Params with Pagination

A very common real-world example:

```text
/products?page=3&limit=20
```

Code:

```tsx
export default async function ProductsPage({
  searchParams,
}: {
  searchParams: Promise<{
    page?: string;
    limit?: string;
  }>
}) {
  const { page = "1", limit = "10" } = await searchParams;

  return (
    <div>
      <p>Page: {page}</p>
      <p>Limit: {limit}</p>
    </div>
  );
}
```

If the URL is:

```text
/products?page=3&limit=20
```

you get:

```text
page = "3"
limit = "20"
```

### Notice something important

Query parameters are **strings**.

So:

```tsx
page
```

is:

```text
"3"
```

not:

```text
3
```

If you need a number:

```tsx
const pageNumber = Number(page);
```

# 8. Catch-All Dynamic Routes

Next.js also supports:

```text
[...slug]
```

Suppose:

```text
app/
└── docs/
    └── [...slug]/
        └── page.tsx
```

Then:

```text
/docs/react
```

gives:

```tsx
{
  slug: ["react"]
}
```

And:

```text
/docs/react/nextjs/routing
```

gives:

```tsx
{
  slug: ["react", "nextjs", "routing"]
}
```

Example:

```tsx
export default async function DocsPage({
  params,
}: {
  params: Promise<{ slug: string[] }>
}) {
  const { slug } = await params;

  return (
    <div>
      {slug.join(" / ")}
    </div>
  );
}
```

Result:

```text
react / nextjs / routing
```

---

# 9. Optional Catch-All

You can also use:

```text
[[...slug]]
```

This allows the route to work even without a slug.

For example:

```text
app/
└── docs/
    └── [[...slug]]/
        └── page.tsx
```

It can handle:

```text
/docs
```

and:

```text
/docs/react
```

and:

```text
/docs/react/nextjs
```

The type becomes:

```tsx
{
  slug?: string[]
}
```

# 10. `params` in Layouts

`params` isn't limited to pages.

You can use it in layouts too.

For example:

```text
app/
└── products/
    └── [id]/
        ├── layout.tsx
        └── page.tsx
```

`layout.tsx`:

```tsx
export default async function ProductLayout({
  children,
  params,
}: {
  children: React.ReactNode;
  params: Promise<{ id: string }>;
}) {
  const { id } = await params;

  return (
    <div>
      <header>
        Product: {id}
      </header>

      {children}
    </div>
  );
}
```

# 11. `searchParams` vs `params` in a Real Application

Imagine you're building an e-commerce application.

You might have:

```text
/products/iphone-17?color=black&storage=256gb
```

You could interpret it as:

```text
params
──────
product = iphone-17

searchParams
────────────
color   = black
storage = 256gb
```

So:

```tsx
export default async function ProductPage({
  params,
  searchParams,
}: {
  params: Promise<{ product: string }>;
  searchParams: Promise<{
    color?: string;
    storage?: string;
  }>;
}) {
  const { product } = await params;

  const { color, storage } = await searchParams;

  return (
    <div>
      <h1>{product}</h1>

      <p>Color: {color}</p>
      <p>Storage: {storage}</p>
    </div>
  );
}
```

This gives you a clean separation:

```text
/products/iphone-17
        │
        └── params → identifies the product

?color=black&storage=256gb
 │
 └── searchParams → modifies the request/view
```

# 12. Reading Search Params in Client Components

There is an important difference here.

In a **Server Component page**, you can use:

```tsx
searchParams
```

directly.

But in a **Client Component**, you generally use:

```tsx
useSearchParams()
```

from `next/navigation`.

Example:

```tsx
"use client";

import { useSearchParams } from "next/navigation";

export default function SearchBox() {
  const searchParams = useSearchParams();

  const query = searchParams.get("q");

  return (
    <div>
      Search: {query}
    </div>
  );
}
```

URL:

```text
/search?q=nextjs
```

Result:

```text
Search: nextjs
```

---

# 13. Reading Dynamic Params in Client Components

For dynamic route parameters, Client Components can use:

```tsx
useParams()
```

Example:

```tsx
"use client";

import { useParams } from "next/navigation";

export default function Product() {
  const params = useParams();

  return (
    <div>
      Product ID: {params.id}
    </div>
  );
}
```

For:

```text
/products/123
```

you get:

```text
params.id → "123"
```

# 14. Server vs Client

A useful mental model:

| Situation        | Server Component | Client Component    |
| ---------------- | ---------------- | ------------------- |
| Dynamic route    | `params`         | `useParams()`       |
| Query string     | `searchParams`   | `useSearchParams()` |
| Navigation       | —                | `useRouter()`       |
| Current pathname | —                | `usePathname()`     |

Example:

### Server

```tsx
export default async function Page({
  params,
  searchParams,
}) {
  const p = await params;
  const s = await searchParams;
}
```

### Client

```tsx
"use client";

import {
  useParams,
  useSearchParams,
} from "next/navigation";

export default function Page() {
  const params = useParams();
  const searchParams = useSearchParams();
}
```

# 15. Getting a Query Parameter

Suppose URL:

```text
/products?search=laptop
```

Client Component:

```tsx
const searchParams = useSearchParams();

const search = searchParams.get("search");
```

Result:

```text
"laptop"
```

For:

```text
/products?search=laptop&sort=price
```

you can do:

```tsx
const search = searchParams.get("search");
const sort = searchParams.get("sort");
```

# 16. Multiple Values

Search parameters can have multiple values:

```text
/products?category=mobile&category=laptop
```

`get()` returns only one value.

Use:

```tsx
const categories = searchParams.getAll("category");
```

Result:

```tsx
["mobile", "laptop"]
```

# 17. Changing Search Params

For interactive filtering, you can use `useRouter()`.

```tsx
"use client";

import { useRouter } from "next/navigation";

export default function Filter() {
  const router = useRouter();

  function filterProducts() {
    router.push("/products?category=mobile");
  }

  return (
    <button onClick={filterProducts}>
      Mobile
    </button>
  );
}
```

Clicking the button navigates to:

```text
/products?category=mobile
```

# 18. `Link` + Search Params

You can also use the Next.js `Link` component:

```tsx
import Link from "next/link";

export default function Filter() {
  return (
    <div>
      <Link href="/products?category=mobile">
        Mobile
      </Link>

      <Link href="/products?category=laptop">
        Laptop
      </Link>
    </div>
  );
}
```

This is often preferable to manually calling `router.push()` for normal navigation.

# 19. Very Important: Params Are Based on Folder Names

Consider:

```text
app/
├── products/
│   ├── page.tsx
│   └── [id]/
│       └── page.tsx
```

These URLs are different:

```text
/products
/products/123
```

For:

```text
/products
```

there is no `[id]`.

For:

```text
/products/123
```

you have:

```tsx
params.id
```

because `[id]` represents that segment.

# 20. Complete Example

Imagine you're building a product page.

Folder:

```text
app/
└── products/
    └── [id]/
        └── page.tsx
```

URL:

```text
/products/101?color=black&sort=popular
```

Page:

```tsx
export default async function ProductPage({
  params,
  searchParams,
}: {
  params: Promise<{ id: string }>;
  searchParams: Promise<{
    color?: string;
    sort?: string;
  }>;
}) {
  const { id } = await params;

  const {
    color = "default",
    sort = "default",
  } = await searchParams;

  return (
    <main>
      <h1>Product {id}</h1>

      <p>Color: {color}</p>

      <p>Sort: {sort}</p>
    </main>
  );
}
```

URL:

```text
/products/101?color=black&sort=popular
```

Data:

```text
params
  id → "101"

searchParams
  color → "black"
  sort → "popular"
```

## The easiest way to remember

```text
URL
│
├── PATH
│
│   /products/123
│             ↑
│             └── params
│
└── QUERY STRING
    ?category=mobile&sort=price
     ↑
     └── searchParams
```

### In Server Components

```tsx
const { id } = await params;

const { category } = await searchParams;
```

### In Client Components

```tsx
const params = useParams();

const searchParams = useSearchParams();
```

**Rule of thumb:**

> If the value is part of the URL's **path and identifies a resource**, use `params`.
> If the value comes after **`?` and controls/filter/sorts the page**, use `searchParams`.

One subtle but important modern Next.js point: **`params` and `searchParams` are request APIs, and in current App Router code you should treat them as promises and `await` them in server components.**
